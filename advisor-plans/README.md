## Verification baseline

The repo has a working one-command verification story
(`bun run check-types && bun run test && bun run lint`, plus
`bunx oxfmt --check` which CI also enforces), 85 test files / ~1.4k cases in
`packages/cms` on PGlite, and CI-enforced coverage floors in
`packages/cms/vitest.config.ts`. Executors must not lower a coverage floor
to get a run green.

The test harness is single-connection PGlite: it cannot interleave two
transactions, so none of the race-condition findings can be reproduced by a
test in this suite. The plans that touch races (006) verify structure and
single-threaded outcomes instead.

## Findings audited but not yet planned

Vetted against the code by the advisor; ordered by leverage. Each is a
candidate for the next planning run.

- **[BUG-03/BUG-04] Root-tree races and unbounded recursive CTEs.** `moveRoot`
  locks only the moving root (`blocks-root-endpoints.ts:797-830`); two
  concurrent opposite moves can create a parent cycle, and the roots CTEs in
  `slug.ts:155-175, 235-262, 278-293` and `revalidation.ts:232-245` have no
  depth bound (unlike `reconstruct-snapshot.ts:195`). Slug uniqueness on
  publish is check-then-act with a non-unique index (`slug.ts:97-115`,
  `publish-branch.ts:85-98, 181-194`). Fix: lock both roots in id order, add
  `depth < N` bounds to the four CTEs. Effort M, risk MED.
- **[BUG-05] `uploadAssets` inserts rows before PUTting to S3**
  (`media.ts:1736-1778`); a mid-batch failure leaves orphan rows that pruning
  never reclaims (it only considers archived assets). `createSignedUpload`
  has the same shape by design of the flow. Fix: PUT then insert for
  `uploadAssets`; a pending state + sweep for signed uploads. Effort M.
- **[BUG-07/BUG-08] `useCmsDocument` save path** (`packages/react/src/editor/cms/use-cms-document.ts`):
  no generation guard on overlapping saves (lines 377-432), so a slower
  earlier save can install an older head; `settlePendingMisses` resolves
  `Promise<string>` consumers with `undefined` (lines 165-169 vs the
  `as Promise<string>` cast at 160). Effort S each.
- **[SEC-03] Comment threads with `rootId = null` bypass scope**
  (`comments.ts:280-291, 708-712`; reachable via `targetType: 'block'` with no
  merge request). Fix: derive `rootId` from `blockId` at creation and drop the
  `isNull(rootId)` escape. Effort S–M, needs a backfill note.
- **[SEC-05] `admin.runPruning` ignores the caller's scope**
  (`admin.ts:69-86`; `runPruningPass` has no scope parameter) while
  `runScheduled` threads it. Decide: thread the scope or document the endpoint
  as operator-only. Effort M, risk MED.
- **[SEC-04] `users.listReviewers` returns the whole user table**
  (`users.ts:123-149`) with no tenant filter; needs a consumer-supplied
  predicate hook. Effort M.
- **[SEC-06] A/B-test plugin keys scoping on the literal `tenant_slug`
  insert column** (`plugins/ab-test/endpoints.ts:85-87, 142-161`); any other
  scoping plugin degrades it to unscoped. Effort M.
- **[SEC-09] Comment mentions are not validated** (`comments.ts:153-159,
442-463`): any user id becomes a notification recipient with the raw
  comment body. Effort S.
- **[PERF-01] `findAssetsInAllPublications` walks every publication in the
  database** on each unpublish (`media/discovery.ts:35-67`); the pruning pass
  answers the same question with one `content_usages` query
  (`pruning.ts:829-841`). Effort S, risk MED (liveness semantics).
- **[PERF-03/PERF-05] Per-link ancestry CTEs on every published render**
  (`links.ts:135-145` → `redirects/resolve.ts:78-116`) and unbounded
  `Promise.all` fan-out in cascade revalidation (`revalidation.ts:396-406,
452-458`); `listRoots` already has the batched CTE to lift
  (`blocks-root-endpoints.ts:505-524`). Effort S–M.
- **[PERF-02] Search reindex on every keystroke-level save, always of the
  default branch** (`search/hooks.ts:71-81`, `index-builder.ts:134-142`).
  Debounce by root and skip non-default branches. Effort M.
- **[PERF-06] Editor dirty check serializes + hashes the whole document per
  version bump** (`packages/react/src/editor/store/store.ts:118-122`,
  `serde.ts:33-47`, `hash.ts:7-27`). Compare `version` to `savedVersion`
  instead. Effort M, unmeasured.
- **[DEP-01] `@createcms/core` peer `react >=18` but `react/tracking.tsx:335`
  uses `useActionState` (React 19).** Raise the peer to `>=19` (breaking,
  minor changeset). Effort S.
- **[DEP-03] Range drift**: dev/example `next ^16.2.0` below the peer floor
  `>=16.2.11`; `@vitest/coverage-v8` / `@vitest/browser-playwright` pinned
  exactly while `vitest` is caret; two zod majors in the lockfile. Effort S.
- **[TEST-03] SigV4 signing has no test** (`storage/s3/utils.ts:48-87`; the
  test S3 server ignores signatures). Golden-vector tests. Effort S.
- **[TEST-06] Scheduled publishing retry/permanent-failure semantics untested**
  (`scheduling.ts:52-60`; 3 tests exist). Effort S.
- **[TEST-04] Upstash sinks, media-optimize and consent auto-read have no
  tests** (~700 lines of exported code). Effort M.
- **[DX-01] No `CLAUDE.md`/`AGENTS.md`.** Outline: repo map from

- **[DX-02] `packages/cms/README.md:31` says Node ≥ 20; `engines` says

## Direction (options for the maintainer, not ranked against bugs)

- **[DIR-01] Scheduled publications cannot be listed or cancelled.**
  `schedulePublication`/`scheduleUnpublish` exist (`publications.ts:330, 393`)
  and `admin.runScheduled` drains them; there is no `listScheduled` or
  `cancelScheduled`. Cancel must respect the same `processedAt IS NULL`
  condition the claim uses (`scheduling.ts:52-57`). Cheapest gap on the list;
  blocks any UI that shows a "scheduled" badge. Effort S.
- **[DIR-04] The editor registry (`apps/docs/registry.json`, 5 items) ships
  page-editing chrome but nothing for the Git-like half** — no diff view,
  branch list, merge request, or approval queue — even though `getDiff`
  returns a purpose-built annotated tree and `guides/visual-diff.mdx` teaches
  users to build it themselves ("bring your own diff UI", `README.md:16`). A
  `diff-view` registry item is the highest-leverage demo asset. Effort M.
- **[DIR-05] The CLI stops at `generate`**; `reference/cli.mdx:58-61` and the
  quickstart hand the user drizzle-kit's generate/migrate split. A thin
  `createcms migrate` (printing the underlying drizzle-kit call) and a
  `createcms doctor` would absorb the first-ten-minutes failures. Effort M;
  CLI coverage floor is 23%, so it needs tests alongside.
- **[DIR-02] No content export/import.** `admin.ts` has only maintenance
  operations; the README warns of data-loss edge cases, and the examples have
  no seed path. Format decision (full history vs published snapshot, media
  by URL vs bundled) is most of the work. Effort L.
- **[DIR-03] Revalidation goes out to Next.js only; no generic outbound
  webhooks or inbound callbacks.** `createHookRunner` already provides the
  event seam; delivery semantics (retry, signing, dead-letter) are the work.
  Could ship as a plugin. Effort M–L.
- **[DIR-06] No audit log** for administrative actions (prune, delete branch,
  merge, publish release, approvals) in a product whose premise is
  attributable history; `MiddlewareResult.userId` is present at every call
  site. Overlaps the notification events; decide which projects from which.
  Effort M.

## Findings considered and rejected

- **TEST-01 "no test for `expectedHeadCommitId`"**: false —
  `blocks.test.ts:2283` covers stale/current/omitted head. Rejected.
- **"Route prelude duplication"** (the same lock-branch/reconstruct/protect
  sequence copy-pasted across routes): false — `core/blocks/guards.ts` is the
  single choke point. Not a finding.
- **`NODE_OPTIONS=--max-old-space-size=6144` on the cms build**: expected for
  `--dts-bundle` over a deeply generic API; not worth chasing unmeasured.
- **Per-commit full snapshot materialization** (`commit-writer.ts:137-155`):
  deliberate read-optimization with pruning as the counterweight. Design, not
  debt.
- **`as any` cluster in `core/schema-builders.ts`**: standard zod generic
  erasure at boundaries whose declared return type is the contract; nothing
  hides a runtime mismatch.
- **Empty catches in `realtime/upstash.ts:87` and `realtime/sse.ts:94`**:
  documented fail-closed/best-effort decisions.
- **`createBranch`/`renameBranch` name check-then-act**: backed by a DB unique
  on `(rootId, name)`; the race degrades to an ugly error, not corruption.
- **Endpoint metadata vs handler behaviour, raw SQL identifiers, realtime
  channel auth, media upload validation on byte-holding paths, notification
  ownership, A/B edge cookies, redirects, CLI file handling, mass assignment,
  committed secrets**: audited and clean (see the security auditor's
  "checked and clean" list in the session; no action).
- **DOCS-02 / DOCS-03**: docs code examples resolve against real exports (61
  import pairs checked); `SECURITY.md` has a working private channel. No
  action.
- **cli/client coverage floors, PGlite singleton test design, CI sharding,
  the private `@createcms/schema` package, "not production-ready"**: decided
  tradeoffs recorded in `vitest.config.ts`, `ci.yml`, and the README.
