The registry ships two editor UIs over the same `@createcms/react` core. The
[shadcn items](/docs/guides/editor-ui) compose shadcn components on Base UI.
`ui-sdk-editor` is built from scratch on [UI SDK](https://github.com/vercel-labs/ui)
(`@ui-sdk/react`), a library of unstyled behaviors from Vercel Labs:
keyboard navigation, focus, dismissal, popups and the ARIA they need. It
meets the same requirements and passes the same browser suite, so you can
compare both on one page.

<Callout type="warn">
  UI SDK is in beta. The items pin `@ui-sdk/react@0.1.0-beta.5`.
</Callout>

## Install

```bash
npx shadcn@latest add https://createcms.dev/r/ui-sdk-editor.json
```

The files land in `components/editor-ui-sdk/`. Declare UI SDK's cascade
layer first in your global stylesheet and import the editor's stylesheet:

```css title="app/globals.css"
@layer ui-sdk;
@import 'tailwindcss';
@import '../components/editor-ui-sdk/editor-ui-sdk.css';
```

```tsx
import { EditorApp } from '@/components/editor-ui-sdk/app';

<EditorApp
  adapter={adapter}
  documentId="home"
  baseVersion={adapter.version('home')}
  schema={schema}
  components={canvasComponents}
/>;
```

`EditorApp` and `EditorAppView` take the same props as the shadcn
`editor-app`. With createCMS, add `ui-sdk-editor-createcms` and render
`CmsEditor` from `components/editor-ui-sdk/app-createcms`. The
[UI SDK demo](/demo/editor/app-ui-sdk) runs on `createMemoryAdapter`, next to
the [shadcn demo](/demo/editor/app).

## How it is built

The editor follows UI SDK's two paths. Where UI SDK ships a component, the
editor uses it. Where it ships none, the part is a UI SDK primitive: one
`definePrimitive` with its state, api and slots, rendered with
`createParts`.

### Primitives

| Primitive | File | What it does |
| --- | --- | --- |
| `editorChrome` | `editor-chrome.ts` | The chrome's state: device, which docked panel shows, the open phone sheet, the command palette page and the commit dialog, each a controlled option the shell holds in React. Every element of the frame gets its `data-slot` from one of its slots (`editor-toolbar`, `editor-surface`, `editor-outline`, `editor-inspector`, `editor-form-surface`, ...). A phone sheet owns a history entry while it is open, so Back closes it. It warns before leaving with unsaved changes. |
| `blockOutline` | `block-outline.ts` | The document as an APG tree on `createRovingFocus`, `createTreeReorder`, `createTypeahead` and `createFocusRecovery`. Selection follows focus; Shift extends it from where it started, Mod with an arrow moves without selecting, Mod+Space adds a block, Mod+A selects all, `*` opens every sibling. Space or Enter picks a block up with everything in it, the arrows move it and change its level, Space drops it and Escape puts it back; screen readers hear every step. Rows drag by the mouse or by the grip on touch. A drop the schema forbids is refused and marked `data-blocked`. Left and Right follow the reading direction. |
| `editorRichText` | `editor-rich-text.ts` | The rich text field around the editor engine: a group named by the field's label, its text as the value agents read and set, and the `{{variable}}` suggestions as a listbox the editor drives. |

`chrome.tsx`, `outline.tsx` and `rich-text.tsx` render them. All three are
agent-ready: `editorChrome` offers `setDevice`, `togglePanel`,
`insertBlock` and `save` and lists the block types it inserts,
`blockOutline` offers `select`, `toggle` and `move` and lists every block
with its text, `editorRichText` offers `setValue`.

### Rich text

UI SDK ships no rich text editor; its Trigger Menu connects to one like
Tiptap through an adapter. So the editing engine stays the one behind
`Editor.Root richText` (Tiptap by default), which also carries shared
editing and the canvas's in-place text. Everything around it is UI SDK:
the field is named through `Field` (`useFieldControl`), the formatting
buttons are `Toggle`s in a `Toolbar` (in the canvas, through
`useRichTextToolbarState`), and the field is a primitive agents can fill.

### UI SDK components

| Part | File | UI SDK |
| --- | --- | --- |
| Shell | `shell.tsx` | `Resizable` panels for palette and outline (left) and the inspector (right). A panel shows or hides whole, by the toolbar buttons, Mod+B (`useShortcut`) or a drag past its minimum. Phones get `Drawer` sheets; the properties sheet snaps to 35, 60 and 100% and only turns modal above 60%, so the canvas stays usable under it. Tablets show the inspector in a side `Drawer`. |
| Toolbar | `toolbar.tsx` | `Toolbar` (one tab stop, arrow keys between items), `Toggle`s for the sidebar and the inspector, a `ToggleGroup` for the device, one shared `Tooltip` with `TooltipShortcut` for every icon button, a pending `Button` for Save, `Dialog` with a pending `DialogClose` for the commit message. Icon buttons stay focusable while disabled (`focusableWhenDisabled`). |
| Commands | `commands.tsx` | One `Command` with pages: every editor command on the first page, with `CommandShortcut`, the block types on the `add` page. Mod+K opens the first page, `/` and every add button the block page; Backspace goes back. |
| Inspector | `inspector.tsx` | `Tabs` for the block and the page. |
| Form | `form.tsx` | Every field is a UI SDK `Field` with `FieldLabel`, `FieldDescription` and `FieldError`; lists, objects, links, media and multiple choice are a `FieldSet` with a `FieldLegend`. |
| Fields | `fields.tsx` | `Input`, `Textarea`, `NumberInput` with step buttons, `Checkbox`, `CheckboxGroup` for multiple choice, `Select`, `DateInput` with the time, a `ColorPicker` that opens from its swatch in a `Popover`. |
| createCMS fields | `fields-createcms.tsx` | References and internal links are a `Combobox` that searches as you type and loads the next page when the list scrolls to its end (`useAsyncOptions`). |
| Canvas chrome | `canvas.tsx` | The block toolbar's More `Menu` with a `Move to…` submenu, named for its block. |
| App | `app.tsx` | `AlertDialog` for a save conflict. Escape doesn't close it: loading the server version or overwriting is a choice, focus starts on Copy mine, and Overwrite stays pending until the save settles. |

Every look lives in `editor-ui-sdk.css`. Components carry `ed-*` classes and
UI SDK's state attributes (`data-open`, `data-highlighted`, `data-selected`,
`data-pressed`, `data-pending`, `data-moving`, `data-blocked`, ...); the
stylesheet keys on both. Theme it through the `--ed-*` tokens at its top,
which default to the shadcn tokens.

## Agents

Connect UI SDK's agent bridge once in the browser and an agent can read the
editor and act in it:

```tsx
import { createAgent } from '@ui-sdk/react/agent';

const agent = createAgent({
  allow: (step) => (step.confirm ? window.confirm(step.confirm) : true),
});

await agent.act({
  steps: [
    { ref: 'Outline', action: 'select', args: ['h1'] },
    { ref: 'Text', action: 'setValue', args: ['Welcome'] },
    { ref: 'Page editor', action: 'insertBlock', args: ['Heading'] },
    { ref: 'Toolbar', action: 'press', args: ['Save'] },
  ],
});
```

Deleting a block, loading the server's version over your changes and
overwriting the server's version carry `data-agent-confirm`, so the bridge
asks a person first. Controls are named so no name holds another's words:
the block toolbar says `Move Heading up`, a link field `Link URL`.

## Differences to know

- **Shortcuts.** The editor's keymap owns its commands' shortcuts; the
  tooltips only show them. Mod+B and Mod+S are bound with `useShortcut`,
  Mod+B not while you type. All of them pause inside a modal dialog and a
  menu.
- **The outline** is the editor's own primitive, not UI SDK's `Tree`, since
  the tree doesn't reorder. Space picks a block up instead of toggling its
  selection; Alt+Up and Alt+Down still move the selected block, as
  everywhere in the editor. It renders every visible row, without
  virtualization.
- **Escape in the palette** first clears the search, then goes back a page,
  then closes.
