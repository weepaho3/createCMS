This guide uploads and serves assets. It assumes a CMS instance (see [Quickstart](/docs/quickstart)) and an S3-compatible bucket. For the model behind it, see [Media](/docs/concepts/media).

### Configure storage

`createCMS` requires a `media` config: your bucket plus a public base URL (a CDN domain). The full shape is in the [configuration reference](/docs/reference/configuration):

```ts title="lib/cms.ts"
media: {
  provider: 'cloudflare',
  accountId: process.env.R2_ACCOUNT_ID!,
  bucketName: process.env.R2_BUCKET!,
  accessKeyId: process.env.R2_KEY!,
  secretAccessKey: process.env.R2_SECRET!,
  publicUrl: process.env.R2_PUBLIC_URL!,
},
```

### Upload from the browser

The React client's `media.useUploadAssets()` returns the client's upload queue: an `upload` function, the entries of every file handed to it, and controls per entry. Under the hood it requests signed URLs and PUTs each file straight to your bucket. The queue belongs to the client, not to the component, so uploads keep running when the component that started them unmounts:

```tsx title="components/uploader.tsx"
'use client';
import { cmsClient } from '@/lib/cms-client';

export function Uploader() {
  const { upload, isUploading, progress, files, reset } =
    cmsClient.media.useUploadAssets();

  return (
    <>
      <input
        type="file"
        multiple
        onChange={async (e) => {
          const entries = await upload(Array.from(e.target.files ?? []));
          const ids = entries.flatMap((entry) =>
            entry.status === 'success' && entry.result ? [entry.result.id] : [],
          );
          console.log('uploaded', ids);
        }}
      />
      {isUploading ? (
        <p>Uploading {Math.round(progress.fraction * 100)}%</p>
      ) : null}
      <ul>
        {files.map((entry) => (
          <li key={entry.id}>
            {entry.name}: {entry.status}
            {entry.error ? ` (${entry.error.code})` : null}
          </li>
        ))}
      </ul>
      <button type="button" onClick={reset}>
        Clear finished
      </button>
    </>
  );
}
```

`upload(files, options?)` takes a `File[]` and optional `{ folderId, signal, optimize, dedupe }`. It resolves with that call's entries once each has settled (or paused), so a caller reads `result.id` from the returned array instead of scanning `files`. Every `upload()` and `replace()` call feeds the same queue, which runs at most four files and six connections at once. Each entry is signed on its own (`createSignedUpload` with that one file, URLs valid for `signedUrlExpiresIn`, default 300 s), PUT, and completed (`completeUpload`) right after its PUT, so a closed tab keeps every file that already landed.

An entry moves through these statuses:

| Status | Meaning |
| --- | --- |
| `queued` | Waiting for a free slot. |
| `preparing` | Hashing (`phase: 'hashing'`, with `dedupe`) or optimizing (`phase: 'optimizing'`, with the [media optimize plugin](/docs/plugins/media-optimize)). Images are optimized one at a time. |
| `signing` | Requesting the signed URL. |
| `uploading` | The PUT is running; `phase` turns `finalizing` once every byte is sent. |
| `completing` | `completeUpload` is creating the row (`phase: 'processing'`). |
| `retrying` | Waiting before the next attempt; `attempt` counts retries and `nextRetryAt` says when (epoch ms). |
| `paused` | Paused by `pause()`, by going offline, or waiting on a duplicate decision (`duplicateOf`). |
| `success`, `error`, `aborted` | Final. `retry()` re-queues `error` entries (and a named `aborted` entry) with a fresh signature. |

`progress` stays at most 0.99 until the row exists; only `success` reaches 1. Network errors, timeouts, 408, 429 and 5xx responses are retried up to five attempts with full-jitter backoff, for the PUT as well as for signing and completing. A PUT without progress for 30 s, or slower than 32 KiB/s overall, times out (`UPLOAD_TIMEOUT`) and is retried. A 429 or an S3 `SlowDown` halves the connection budget (`budget`), which grows back by one every 30 s. A PUT rejected because its signature expired is signed again once (`UPLOAD_EXPIRED` if it expires a second time).

Aborting an entry (`abort(id)`, `abort()` for all, or the call's `signal`) stops its PUT and calls [`abortUpload`](/docs/reference/media#abortupload), which deletes any bytes that already landed. Pausing does the same and restarts the PUT from the beginning on `resume()`. An entry whose bytes landed is no longer abortable: its row is created regardless. The queue pauses every entry when the browser goes offline and resumes them when it is back, and asks the user to confirm leaving the page only while bytes are moving or a row is being created. Objects of uploads that are never completed or aborted (a crashed tab) are removed later by the [pruning sweep](/docs/concepts/data-retention).

With `dedupe: true`, files up to 64 MiB are hashed and checked against [`findDuplicates`](/docs/reference/media#findduplicates) first. An exact match pauses the entry with `duplicateOf`; settle it with `resolveDuplicate(id, decision)`: `{ action: 'use-existing', assetId }` finishes with that asset, `{ action: 'upload-copy' }` uploads anyway, `{ action: 'replace', assetId }` uploads the file as new bytes of that asset. When the storage verifies checksums on PUT, the hash is also signed into the URL and stored on the asset.

Uploads are validated server-side against the limits (defaults: `maxFileSize` 4 MB, `allowedMimeTypes` an explicit image/video/PDF allowlist that **excludes SVG**, see [Configuration](/docs/reference/configuration#media)); a rejected file ends `error` with the server code (`FILE_TOO_LARGE` or `INVALID_FILE_TYPE`). `maxFiles` limits a single `createSignedUpload` call, which the browser client always makes with one file. A PUT that fails on the network after the retries is `NETWORK_ERROR`; any other PUT failure is `UPLOAD_FAILED`. New assets are created **private**.

| Field | Type | Description |
| --- | --- | --- |
| `upload` | `(files: File[], options?: CMSMediaUploadOptions) => Promise<CMSMediaUploadFileState[]>` | Queue new assets; resolves with that call's entries. Options: `folderId`, `signal` (aborts this call's entries), `optimize` (`false` skips the optimize plugin), `dedupe`. |
| `replace` | `(assetId, file, options?) => Promise<CMSMediaUploadFileState>` | Queue new bytes for an existing asset (`createSignedReplace` + `commitReplace`). Options: `signal`, `optimize`, `revisionNote`. |
| `isUploading` | `boolean` | `true` while any entry is active (`queued` through `completing`, or `retrying`). |
| `progress` | `{ loaded, total, fraction, bytesPerSecond, eta }` | Bytes across every entry that is not `error` or `aborted`. `bytesPerSecond` is a smoothed rate (`null` until measured); `eta` is seconds left, `null` in the first 2.5 s of a transfer. |
| `files` | `CMSMediaUploadFileState[]` | Every entry since the last `reset()`, in call order: `id`, `kind` (`create` or `replace`), `file`, `name`, `size`, `type`, `status`, `phase`, `loaded`, `total`, `progress`, `attempt`, `nextRetryAt`, `folderId`, `targetAssetId?`, `sha256?`, `duplicateOf?`, `error?` (`{ code, message, retryable, timedOut? }`), `optimize?` and `result?` (`{ id, slug, objectKey }`). |
| `error` | `unknown` | The last error that failed an entry since the last `upload`, `replace` or `reset`; `null` otherwise. |
| `budget` | `number` | Connections the queue may use now: 6, halved while throttled. |
| `abort` | `(id?: string) => void` | Aborts one entry, or every unfinished entry. |
| `retry` | `(id?: string) => void` | Re-queues one failed or aborted entry, or every failed entry. |
| `pause` / `resume` | `(id?: string) => void` | Pauses or resumes one entry, or all. |
| `resolveDuplicate` | `(id, decision) => void` | Settles an entry paused on a duplicate. |
| `reset` | `() => void` | Drops `success`, `error` and `aborted` entries and clears `error`; other entries stay. |

The vanilla client exposes the same queue as the nanostores atom `client.media.uploadState`. After a reload, `takeInterruptedUploads()` (from `@createcms/core/react`, or `@createcms/core` for the vanilla client) returns the name, size and kind of every upload that was unfinished when the page was last hidden, so the app can ask the user to pick those files again.

### Optimize before upload

Add the [media optimize plugin](/docs/plugins/media-optimize) and `upload` resizes, compresses and converts images in the browser before signing; see [Media optimize: Usage](/docs/plugins/media-optimize#usage).

### Serve an asset

Serve assets through the CMS **gate**: `GET /media/asset/{id}`, a public redirect to the object, addressed by the **asset id** (which is exactly what content stores). Use this in content and on public pages — it enforces `status` (a `private` asset returns `ASSET_ACCESS_DENIED`; flip one to `public` with `updateAssetsStatus`) and honors `?format=` and `?w=` by resolving a **pre-uploaded** variant asset (falling back to the original). There is no on-the-fly transform: produce variants ahead of time (for example with the optimize plugin).

```html
<img src="https://your-cms.example.com/media/asset/ast_6t4x5a98n2io352uhbkq" />
```

`listAssets` and the upload responses also return a **direct** `url` per asset — your `publicUrl` joined with the asset's `objectKey`. It bypasses the gate (no status check, no transforms, ignores query strings), so it is for **internal tooling** like a media-library admin UI showing thumbnails of assets you manage — not for embedding in content:

```ts
const thumb = asset.url; // direct object URL — admin/library display only
// e.g. https://cdn.example.com/welcome-hero
```

### Upload from the server

For server-initiated uploads, call the API directly. `createSignedUpload` returns presigned PUT URLs and a token per file (you PUT the bytes with the returned headers, then pass the tokens to `completeUpload`, which creates the rows); `uploadAssets` sends the bytes through the server (each file needs a `buffer: Blob | ArrayBuffer`):

```ts
const { uploads } = await cms.api.media.createSignedUpload({
  body: { files: [{ name: 'hero.jpg', size: file.size, type: 'image/jpeg' }] },
});
await fetch(uploads[0].signedUrl, {
  method: 'PUT',
  headers: uploads[0].headers,
  body: file,
});
const { assets, errors } = await cms.api.media.completeUpload({
  body: { uploads: [{ token: uploads[0].token }] },
});
```
