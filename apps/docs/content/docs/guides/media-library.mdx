title: Media library
description: Install the styled media library and media picker from the createCMS shadcn registry.
---

`@createcms/react/media` ships the headless parts (`Media.Root`, `Media.Grid`, `Folder.Tree`, `Intake.Dropzone`, `Bulk.Bar`, ...; see the [Media reference](/docs/reference/react-media)). The registry adds two styled items on top:

- `media-library`: a wrapper per `Media.*` part plus `MediaLibraryLayout`, a composed default view. None of them render `Media.Root`.
- `media-picker`: a dialog control that owns its own `Media.Root` and returns one selected asset id.

## Install

```bash
npx shadcn@latest add https://createcms.dev/r/media-library.json
npx shadcn@latest add https://createcms.dev/r/media-picker.json
```

The CLI installs the shadcn dependencies (`progress`, `badge`, `breadcrumb`, `alert`, `alert-dialog`, `dropdown-menu`, ...) automatically; `media-picker` pulls in `media-library`. While developing the docs site locally, swap `https://createcms.dev` for `http://localhost:4000`.

Both items need a `@createcms/react` release that contains the `/media` entry point.

## The default layout

`MediaLibraryLayout` composes the folder tree, the toolbar (breadcrumbs, search, sort, new folder), filter chips, the dropzone with file and folder inputs, folder cards, the asset grid with upload tiles, the empty and error states, load more, the upload list, the bulk bar with its "Move to" dialog, the undo toast, the window drop overlay and the folder-structure prompt. Render it inside `Media.Root` with `cmsClient.media`:

```tsx
'use client';

import { Media } from '@createcms/react/media';
import { createHistoryFilterAdapter } from '@createcms/react/media/core';
import * as React from 'react';

import { cmsClient } from '@/lib/cms-client';
import { MediaLibraryLayout } from '@/components/media-library';

export function MediaPage() {
  // Folder, search, filters and sort live in the URL, so a copied link
  // opens the same view and back and forward work.
  const [filterUrl] = React.useState(() => createHistoryFilterAdapter());
  return (
    <Media.Root client={cmsClient.media} selection="multiple" filterUrl={filterUrl}>
      <MediaLibraryLayout />
    </Media.Root>
  );
}
```

`Media.Root` reads `client` once at mount; render it with a different `key` to swap clients. The [media demo](/demo/media) runs this composition against an in-memory client.

## Composing by hand

Every wrapper is exported on its own and keeps the part's `data-*` attributes, so a custom view mixes them with plain elements:

```tsx
import { Media } from '@createcms/react/media';

import {
  MediaAssetCard,
  MediaBreadcrumbs,
  MediaDropzone,
  MediaEmpty,
  MediaError,
  MediaGrid,
  MediaLoadMore,
  MediaBulkBar,
  MediaSearch,
  MediaUploadList,
} from '@/components/media-library';

<Media.Root client={cmsClient.media} selection="multiple">
  <div className="flex items-center gap-2">
    <MediaBreadcrumbs className="mr-auto" />
    <MediaSearch />
  </div>
  <MediaError />
  <MediaDropzone accept="image/*" maxFiles={5} />
  <MediaGrid>{(asset) => <MediaAssetCard key={asset.id} asset={asset} />}</MediaGrid>
  <MediaEmpty />
  <MediaLoadMore />
  <MediaUploadList />
  <MediaBulkBar />
</Media.Root>
```

| Export | Wraps | Notes |
| --- | --- | --- |
| `MediaFolderTree` | `Folder.Tree`, `Folder.Item`, `Folder.Toggle`, `Folder.Rename` | Indented rows, a drop ring on `data-drop-over`; `mode="pick"` serves the "Move to" dialog |
| `MediaBreadcrumbs`, `MediaCrumb` | `Media.Breadcrumbs`, `Media.Crumb` + shadcn `Breadcrumb` | Deep paths collapse into a `DropdownMenu`; crumbs are drop targets |
| `MediaSearch` | `Media.Search` as shadcn `Input` | |
| `MediaSortSelect` | shadcn `Select` bound to `useMediaFilter` | Newest, oldest, name and largest first |
| `MediaNewFolder` | `Folder.Create` | A button that turns into an inline name field |
| `MediaFilterBar` | `Filter.Chip`, `Filter.Clear`, `Filter.Scope` | Chips with facet counts for images, videos, documents, AI-generated, not in use and missing alt text |
| `MediaFolderList`, `MediaFolderCard` | `Media.FolderList`, `Media.Folder` | Drop targets for assets, folders and files |
| `MediaGrid`, `MediaAssetCard`, `MediaUploadTile` | `Media.Grid`, `Media.Item`, `Media.Thumbnail`, `Selection.Checkbox`, `Media.UploadTile` | Cells are placed by the layout engine; the card fills its cell |
| `MediaDropzone`, `MediaDropOverlay`, `MediaFolderPrompt` | `Intake.Dropzone`, `Intake.Input`, `Intake.FolderInput`, `Intake.Overlay`, `Intake.FolderPrompt` | Dashed zone, full-window overlay, recreate-or-flatten dialog |
| `MediaUploadList` | `Media.UploadList` + shadcn `Progress` | One abort and one clear button per list |
| `MediaEmpty`, `MediaError`, `MediaMutationError`, `MediaLoadMore` | the matching parts | Errors render a destructive `Alert` with Retry or Dismiss |
| `MediaBulkBar`, `MediaMoveDialog`, `MediaOutcome` | `Selection.*`, `Bulk.Bar`, `Bulk.Action`, `Bulk.Outcome` | See below |

Every visible string comes from the media messages catalog (see [Messages](/docs/reference/react-media#messages)). Pass a partial catalog and a locale to `Media.Root` to translate the library; sizes, numbers and plurals follow the locale. `MediaPicker` takes the same `messages` and `locale` props.

```tsx
import { mediaMessagesDe } from '@/lib/media-messages-de';

<Media.Root client={cmsClient.media} messages={mediaMessagesDe} locale="de-DE">
  <MediaLibraryLayout />
</Media.Root>
```

`apps/docs/src/lib/media-messages-de.ts` is a complete German catalog, typed as `MediaMessages` so the compiler flags any untranslated key.

`MediaUploadList` passes the shadcn `Progress` as the `render` element of `Media.UploadProgress`. Both set `role="progressbar"` and `aria-value*`; the part's attributes win, so the bar announces the file name and, on an error, `upload.failed` with the translated error code (never the server message).

### Selection actions

`MediaBulkBar` appears once something is selected: the count, **Select all 312** when more assets match than are loaded, the registered bulk actions (**Move to...**, **Make public**, **Make private**, **Download**, **Archive**) and **Clear**. Disabled actions say why in their tooltip ("All selected assets are public."). **Archive** asks first; when the server skips assets because they are in use, a second dialog lists them and **Archive anyway** archives them with `force`. **Move to...** opens `MediaMoveDialog`, a folder tree in pick mode where Enter moves. Results show in `MediaOutcome`, a toast with **Undo** ("4 assets moved to Products. Undo"), and are announced to screen readers; after a removal the focus moves to the next asset. Register your own actions with `store.registries.assetActions.register(...)`.

### Thumbnails

`MediaAssetCard` loads the 320 px WebP rendition through the asset endpoint, never the bucket URL of a private asset, with a `srcset` of the existing renditions and the dominant colour until it loaded. Assets without renditions fall back to `assetUrl` on `Media.Root` (the gate path by default).

## The picker in a field control

`MediaPicker` owns a `Dialog` and a `Media.Root` with `selection="single"`. Its content is a reduced layout (breadcrumbs, search, dropzone, grid, load more, upload list, error) with **Select** and **Cancel** in the footer; **Select** calls `onChange(id)` and closes. When a drop or pick uploads exactly one file, that asset is selected right away.

```tsx
import type { FieldControlProps } from '@createcms/react/editor';

import { Button } from '@/components/ui/button';
import { MediaPicker } from '@/components/media-library';

function HeroImageField(props: FieldControlProps<'image'>) {
  return (
    <MediaPicker
      client={cmsClient.media}
      value={props.value}
      onChange={props.onChange}
      accept="image/*"
      trigger={<Button variant="outline">Choose image</Button>}
    />
  );
}
```

`accept` works like the file input attribute: its types (`image/*`, exact types) filter the grid on the server, and the dropzone rejects other files. The picker keeps its filter in memory and never touches the page URL. Enter or a double click on an asset selects it right away.

`editor-form`'s image control uses the picker. `CmsSourcesProvider` takes an optional `media` client for it:

```tsx
<CmsSourcesProvider sources={sources} media={cmsClient.media}>
  <Form blockId={blockId} />
</CmsSourcesProvider>
```

Without `media`, the picker runs on a read-only adapter over `sources.assets` (`sourcesMediaClient`): offset paging as the cursor, text search, no folders and no type filter, uploads through `sources.assets.useUpload`, and every mutation rejected with `Not supported by this media source`. `CmsEditor` passes `client.media` through automatically when it has the full `MediaClient` surface (`listFolders`, `createFolder`, `moveAssets`, `archiveAssets`, `updateAssetsStatus`, `useUploadAssets`).
