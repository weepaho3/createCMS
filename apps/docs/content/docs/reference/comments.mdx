---
title: Comments API
description: Threaded review comments on merge requests and blocks.
---

Comment methods let reviewers open threads on a merge request or a block, reply, mention users, and resolve or reopen the discussion. They live at `cms.api.<collection>.<method>` and mirror on the client at `client.<collection>.<method>` with identical types. Examples below use `pages` as the sample collection.

These endpoints operate on comment threads and messages, not on content commits, so no method returns a `commit` envelope.

### Open a Comment Thread [#createcommentthread]

Open a new review thread with an initial message, so reviewers can flag something on a merge request or a block. `targetType` picks the anchor: `'mergeRequest'` requires `mergeRequestId`, `'block'` requires `blockId`. Anyone you list in `mentions` gets a notification.

<APIMethod
  method="POST"
  path="/{collection}/createCommentThread"
  fn="createCommentThread"
  resource="comment"
  operation="create"
  args={`{
  body: {
    targetType: 'mergeRequest', // required
    mergeRequestId: 'mr_8fd21c', // required when targetType is 'mergeRequest'
    body: 'Can we tighten the hero copy before merging?', // required
    mentions: ['user_editor'],
  },
}`}
  returns={{
    thread: { type: 'CommentThread', description: 'The new thread: `{ id, status, targetType, rootId, mergeRequestId, blockId, commitId, createdBy, createdAt, ... }`.' },
    message: { type: 'CommentMessage', description: 'The initial message, with its resolved `mentions` (the author is stripped out).' },
  }}
  params={{
    targetType: { type: "'mergeRequest' | 'block'", required: true, description: 'What the thread is attached to.' },
    body: { type: 'string', required: true, description: 'Initial message text (non-empty).' },
    mergeRequestId: { type: 'string', description: "Merge request to attach to. Required when targetType is 'mergeRequest'; also infers rootId." },
    blockId: { type: 'string', description: "Block to attach to. Required when targetType is 'block'." },
    commitId: { type: 'string', description: 'Optional commit to pin the thread to a specific snapshot.' },
    rootId: { type: 'string', description: 'Optional root ID. Inferred from the merge request when omitted.' },
    mentions: { type: 'string[]', description: 'User IDs to mention in the initial message.' },
  }}
/>

### Reply to a Thread [#createcommentmessage]

Reply to an existing thread, optionally nested under a parent message. The thread's creator and every mentioned user get notified.

<APIMethod
  method="POST"
  path="/{collection}/createCommentMessage"
  fn="createCommentMessage"
  resource="comment"
  operation="create"
  args={`{
  body: {
    threadId: 'thr_1a2b3c', // required
    body: 'Updated, ready for another look.', // required
  },
}`}
  returns={{
    message: { type: 'CommentMessage', description: 'The new reply, with its resolved `mentions` and `parentMessageId` when nested.' },
  }}
  params={{
    threadId: { type: 'string', required: true, description: 'Thread to reply in.' },
    body: { type: 'string', required: true, description: 'Message text (non-empty).' },
    parentMessageId: { type: 'string', description: 'Parent message for a nested reply.' },
    mentions: { type: 'string[]', description: 'User IDs to mention in this message.' },
  }}
/>

### List Comment Threads [#listcommentthreads]

Page through comment threads, filtered by what they're attached to (merge request, block, commit, root), by `status`, or by who was mentioned. Each thread comes back with its message count and first/latest message, so you can render a list without a second round-trip. Every query field is optional.

<APIMethod
  method="GET"
  path="/{collection}/listCommentThreads"
  fn="listCommentThreads"
  resource="comment"
  operation="read"
  args={`{
  query: {
    status: 'open',
    limit: 50,
  },
}`}
  returns={{
    threads: { type: 'CommentThreadSummary[]', description: 'The threads on this page, newest first. Each carries `messageCount`, `firstMessage`, `latestMessage`, and enriched `createdByUser` / `resolvedByUser`.' },
    total: { type: 'number', description: 'Total threads matching the filters, ignoring limit/offset.' },
    hasMore: { type: 'boolean', description: 'Whether more threads exist after this page.' },
  }}
  params={{
    mergeRequestId: { type: 'string', description: 'Filter by merge request.' },
    blockId: { type: 'string', description: 'Filter by block.' },
    commitId: { type: 'string', description: 'Filter by commit.' },
    rootId: { type: 'string', description: 'Filter by root.' },
    status: { type: "'open' | 'resolved'", description: 'Filter by thread status.' },
    mentionedUserId: { type: 'string', description: 'Only threads mentioning this user.' },
    limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
    offset: { type: 'number', default: '0', description: 'Rows to skip.' },
  }}
/>

### Get a Thread with Its Messages [#getcommentthread]

Load a single thread together with all of its messages in chronological order, so you can render the full discussion. Deleted messages still come back, but with their `body` masked to `null`.

<APIMethod
  method="GET"
  path="/{collection}/getCommentThread"
  fn="getCommentThread"
  resource="comment"
  operation="read"
  args={`{
  query: { threadId: 'thr_1a2b3c' }, // required
}`}
  returns={{
    thread: { type: 'CommentThread', description: 'The thread, with enriched `createdByUser` / `resolvedByUser`.' },
    messages: { type: 'CommentMessage[]', description: 'Every message in the thread, oldest first. Deleted messages come back with `body: null`; author profiles attach as `authorUser` when user enrichment is on.' },
  }}
  params={{
    threadId: { type: 'string', required: true, description: 'Thread to fetch.' },
  }}
/>

### Edit a Message [#updatecommentmessage]

Edit the text of a message you wrote, and optionally replace its mentions. Only the original author may edit, and system messages cannot be edited.

<APIMethod
  method="POST"
  path="/{collection}/updateCommentMessage"
  fn="updateCommentMessage"
  resource="comment"
  operation="update"
  args={`{
  body: {
    messageId: 'msg_9f8e7d', // required
    body: 'Revised: tightened the hero copy.', // required
  },
}`}
  returns={{
    message: { type: 'CommentMessage', description: 'The edited message, with `editedAt` set and its current `mentions`.' },
  }}
  params={{
    messageId: { type: 'string', required: true, description: 'Message to edit.' },
    body: { type: 'string', required: true, description: 'New message text (non-empty).' },
    mentions: { type: 'string[]', description: "When provided, replaces the message's mentions." },
  }}
/>

### Resolve a Thread [#resolvecommentthread]

Mark a thread as resolved once its discussion is settled. A system message is appended recording who resolved it, and you get both the updated thread and that message back.

<APIMethod
  method="POST"
  path="/{collection}/resolveCommentThread"
  fn="resolveCommentThread"
  resource="comment"
  operation="update"
  args={`{
  body: { threadId: 'thr_1a2b3c' }, // required
}`}
  returns={{
    thread: { type: 'CommentThread', description: "The thread, now resolved: `status: 'resolved'` with `resolvedBy` and `resolvedAt` set." },
    message: { type: 'CommentMessage', description: "The appended system message recording the resolution (`messageType: 'system'`, `systemType: 'threadResolved'`)." },
  }}
  params={{
    threadId: { type: 'string', required: true, description: 'Thread to resolve.' },
  }}
/>

<APIMethod
  method="POST"

  body: { threadId: 'thr_1a2b3c' }, // required
}`}

### Delete a Thread [#deletecommentthread]

Soft-delete a thread so it drops out of list and get. Its messages and mentions stay in the database and are removed only when the owning root is pruned.

<APIMethod
  method="POST"
  path="/{collection}/deleteCommentThread"
  fn="deleteCommentThread"
  resource="comment"
  operation="delete"
  args={`{
  body: { threadId: 'thr_1a2b3c' }, // required
}`}
  returns={{
    threadId: { type: 'string', description: 'The id of the soft-deleted thread.' },
  }}
  params={{
    threadId: { type: 'string', required: true, description: 'Thread to soft-delete.' },
  }}
/>

### Delete a Message [#deletecommentmessage]

Soft-delete a single message so its body is masked on retrieval. Only the original author may delete, and system messages cannot be deleted.

<APIMethod
  method="POST"
  path="/{collection}/deleteCommentMessage"
  fn="deleteCommentMessage"
  resource="comment"
  operation="delete"
  args={`{
  body: { messageId: 'msg_9f8e7d' }, // required
}`}
  returns={{
    message: { type: 'CommentMessage', description: 'The soft-deleted message, returned with `body: null` and `deletedAt` set.' },
  }}
  params={{
    messageId: { type: 'string', required: true, description: 'Message to soft-delete.' },
  }}
/>

### List a User's Mentions [#listmentions]

Page through the mentions a user has received, each with the message and thread it came from, so you can build a mentions inbox. Filter to a single thread with `threadId`.

<APIMethod
  method="GET"
  path="/{collection}/listMentions"
  fn="listMentions"
  resource="comment"
  operation="read"
  args={`{
  query: {
    mentionedUserId: 'usr_1', // required
    limit: 50,
  },
}`}
  returns={{
    mentions: { type: 'Mention[]', description: 'The mentions on this page, newest first. Each has `id`, `mentionedUserId`, `mentionedBy`, `createdAt`, plus the full `message` and `thread` it belongs to.' },
    total: { type: 'number', description: 'Total mentions matching the filters, ignoring limit/offset.' },
    hasMore: { type: 'boolean', description: 'Whether more mentions exist after this page.' },
  }}
  params={{
    mentionedUserId: { type: 'string', required: true, description: 'User whose mentions to list.' },
    threadId: { type: 'string', description: 'Restrict to mentions in one thread.' },
    limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
    offset: { type: 'number', default: '0', description: 'Rows to skip.' },
  }}
/>
