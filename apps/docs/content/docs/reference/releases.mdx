---
title: Releases API
description: Group multiple entries' branches into a bundle and publish them atomically.
---

A release bundles several entries (roots), each pinned to one of its branches, so they can be published together in a single atomic operation. These methods live on the system namespace at `cms.api.releases.<method>` and mirror on the client as `client.releases.<method>` with identical types. A release is not per-collection: one release may span entries from different collections.

A release starts as a `draft` you build up with items, then flips to `published` when `publishRelease` succeeds. Item mutations only work while the release is a draft. Publishing points each item at its branch's existing head commit rather than creating new ones, so none of these methods returns a `commit` envelope.

### Create a Release [#createrelease]

Start a new, empty draft release and get it back to work with. Fill it with entries using `addToRelease` or `setReleaseItems`, then ship them together with `publishRelease`.

<APIMethod
  method="POST"
  path="/releases/createRelease"
  fn="createRelease"
  collection="releases"
  resource="release"
  operation="create"
  args={`{
  body: { title: 'Spring launch' }, // required
}`}
  returns={{
    release: { type: 'Release', description: "The new draft release: `{ id, title, status: 'draft', createdBy, createdAt, publishedAt: null }`." },
  }}
  params={{
    title: { type: 'string', required: true, description: 'Human-readable name for the release (non-empty).' },
  }}
/>

The returned `release` carries `id`, `title`, `status: 'draft'`, `createdBy`, `createdAt`, and `publishedAt` (null until published).

### Add an Entry to a Release [#addtorelease]

Add one entry to a draft release, pinned to the branch you want it to publish from. It upserts on `(releaseId, rootId)`, so re-adding a root that's already in the release just swaps which branch it will publish, and the root and branch are validated up front. Fails with `RELEASE_NOT_FOUND`, `RELEASE_NOT_DRAFT`, `ROOT_NOT_FOUND`, or `BRANCH_NOT_FOUND`.

<APIMethod
  method="POST"
  path="/releases/addToRelease"
  fn="addToRelease"
  collection="releases"
  resource="release"
  operation="update"
  args={`{
  body: {
    releaseId: 'rel_abc123', // required
    rootId: 'root_home', // required
    branchId: 'br_main', // required
  },
}`}
  returns={{
    item: { type: 'ReleaseItem', description: 'The created or updated member: `{ id, releaseId, rootId, branchId }`.' },
  }}
  params={{
    releaseId: { type: 'string', required: true, description: 'The draft release to add to.' },
    rootId: { type: 'string', required: true, description: 'The root (entry) to include.' },
    branchId: { type: 'string', required: true, description: 'The branch of that root to publish when the release publishes.' },
  }}
/>

The returned `item` carries `id`, `releaseId`, `rootId`, and `branchId`.

### Remove an Entry from a Release [#removefromrelease]

Drop one entry (by `rootId`) from a draft release. Fails with `RELEASE_NOT_FOUND` or `RELEASE_NOT_DRAFT`.

<APIMethod
  method="POST"
  path="/releases/removeFromRelease"
  fn="removeFromRelease"
  collection="releases"
  resource="release"
  operation="update"
  args={`{
  body: {
    releaseId: 'rel_abc123', // required
    rootId: 'root_home', // required
  },
}`}
  returns={{
    removed: { type: 'boolean', description: 'Whether a matching item was deleted — `true` if the root was in the release, `false` otherwise.' },
  }}
  params={{
    releaseId: { type: 'string', required: true, description: 'The draft release.' },
    rootId: { type: 'string', required: true, description: 'The root to remove.' },
  }}
/>

The returned `removed` is `true` when a matching item was deleted, `false` otherwise.

### Set a Release's Items [#setreleaseitems]

Replace a draft release's entire member list in one shot. Every item is validated first, then the old items are cleared and the new set inserted in a single transaction. Duplicate roots are rejected with `RELEASE_DUPLICATE_ROOT`; it also fails with `RELEASE_NOT_FOUND`, `RELEASE_NOT_DRAFT`, `ROOT_NOT_FOUND`, or `BRANCH_NOT_FOUND`.

<APIMethod
  method="POST"
  path="/releases/setReleaseItems"
  fn="setReleaseItems"
  collection="releases"
  resource="release"
  operation="update"
  args={`{
  body: {
    releaseId: 'rel_abc123', // required
    items: [{ rootId: 'root_home', branchId: 'br_main' }], // required
  },
}`}
  returns={{
    items: { type: 'ReleaseItem[]', description: 'The new member set after replacement — one `{ id, releaseId, rootId, branchId }` per item (empty if you passed an empty list).' },
  }}
  params={{
    releaseId: { type: 'string', required: true, description: 'The draft release.' },
    items: { type: '{ rootId: string; branchId: string }[]', required: true, description: 'The complete new member list. Replaces all existing items; roots must be unique.' },
  }}
/>

### Get a Release [#getrelease]

Fetch a single release together with its items. Fails with `RELEASE_NOT_FOUND`.

<APIMethod
  method="GET"
  path="/releases/getRelease"
  fn="getRelease"
  collection="releases"
  resource="release"
  operation="read"
  args={`{
  query: { releaseId: 'rel_abc123' }, // required
}`}
  returns={{
    release: { type: 'Release', description: 'The release row: `{ id, title, status, createdBy, createdAt, publishedAt }`.' },
    items: { type: 'ReleaseItem[]', description: 'The entries in the release, each `{ id, releaseId, rootId, branchId }`.' },
  }}
  params={{
    releaseId: { type: 'string', required: true, description: 'The release to fetch.' },
  }}
/>

### List Releases [#listreleases]

Page through your releases, newest first, optionally narrowed to one status. Every query field is optional.

<APIMethod
  method="GET"
  path="/releases/listReleases"
  fn="listReleases"
  collection="releases"
  resource="release"
  operation="read"
  args={`{
  query: { status: 'draft', limit: 20 },
}`}
  returns={{
    releases: { type: 'Release[]', description: 'The releases on this page, newest first.' },
    total: { type: 'number', description: 'Total releases matching the status filter, ignoring limit/offset.' },
    hasMore: { type: 'boolean', description: 'Whether more releases exist after this page.' },
  }}
  params={{
    status: { type: "'draft' | 'published'", description: 'Filter by release status.' },
    limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
    offset: { type: 'number', default: '0', description: 'Rows to skip.' },
  }}
/>

### Publish a Release [#publishrelease]

Publish every entry in the release atomically. Each item runs the same publish machinery as `pages.publishBranch`, all inside one database transaction: if any item fails (for example an unapproved branch under a policy that requires approval), the whole set rolls back and nothing goes live. On success the release flips to `published`. Fails with `RELEASE_NOT_FOUND`, `RELEASE_NOT_DRAFT`, `RELEASE_EMPTY`, `ROOT_NOT_FOUND`, `BRANCH_NOT_FOUND`, or `PUBLICATION_APPROVAL_REQUIRED`.

<APIMethod
  method="POST"
  path="/releases/publishRelease"
  fn="publishRelease"
  collection="releases"
  resource="release"
  operation="update"
  args={`{
  body: { releaseId: 'rel_abc123' }, // required
}`}
  returns={{
    release: { type: 'Release', description: "The updated release, now `status: 'published'` with a set `publishedAt`." },
    publications: { type: 'Publication[]', description: 'One publication per item: `{ rootId, branchId, commitId, publishedBy, publishedAt, branchName }`.' },
  }}
  params={{
    releaseId: { type: 'string', required: true, description: 'The draft release to publish.' },
    publishedBy: { type: 'string', description: 'Fallback actor id, used only when the request has no session user (the request user takes precedence).' },
  }}
/>

The updated `release` has `status: 'published'` and a set `publishedAt`; `publications` holds one publication per item.
