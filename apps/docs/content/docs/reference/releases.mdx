---
title: Releases API
description: Group multiple entries' branches into a bundle and publish them atomically.
---

A release bundles several entries (roots), each pinned to one of its branches, so they can be published together in a single atomic operation. These methods live on the system namespace at `cms.api.releases.<method>` and mirror on the client as `client.releases.<method>` with identical types. A release is not per-collection: one release may span entries from different collections.

A release starts as a `draft` you build up with items, then flips to `published` when `publishRelease` succeeds. Item mutations only work while the release is a draft. Publishing points each item at its branch's existing head commit rather than creating new ones, so none of these methods returns a `commit` envelope.

### `createRelease`

Creates a new empty draft release. Add entries to it with `addToRelease` or `setReleaseItems`, then publish with `publishRelease`.

<APIMethod method="POST" path="/releases/createRelease" resource="release" operation="create" returns="{ release }" params={{
  title: { type: 'string', required: true, description: 'Human-readable name for the release (non-empty).' },
}} />

```ts
const { release } = await cms.api.releases.createRelease({
  body: { title: 'Spring launch' },
});
```

The returned `release` carries `id`, `title`, `status: 'draft'`, `createdBy`, `createdAt`, and `publishedAt` (null until published).

### `addToRelease`

Adds (or updates) one entry in a draft release. Upserts on `(releaseId, rootId)`: re-adding a root already in the release swaps which branch it will publish. The root and branch are validated up front. Fails with `RELEASE_NOT_FOUND`, `RELEASE_NOT_DRAFT`, `ROOT_NOT_FOUND`, or `BRANCH_NOT_FOUND`.

<APIMethod method="POST" path="/releases/addToRelease" resource="release" operation="update" returns="{ item }" params={{
  releaseId: { type: 'string', required: true, description: 'The draft release to add to.' },
  rootId: { type: 'string', required: true, description: 'The root (entry) to include.' },
  branchId: { type: 'string', required: true, description: 'The branch of that root to publish when the release publishes.' },
}} />

```ts
const { item } = await cms.api.releases.addToRelease({
  body: { releaseId: release.id, rootId: 'root_123', branchId: 'branch_456' },
});
```

The returned `item` carries `id`, `releaseId`, `rootId`, and `branchId`.

### `removeFromRelease`

Removes one entry (by `rootId`) from a draft release. Fails with `RELEASE_NOT_FOUND` or `RELEASE_NOT_DRAFT`.

<APIMethod method="POST" path="/releases/removeFromRelease" resource="release" operation="update" returns="{ removed }" params={{
  releaseId: { type: 'string', required: true, description: 'The draft release.' },
  rootId: { type: 'string', required: true, description: 'The root to remove.' },
}} />

The returned `removed` is `true` when a matching item was deleted, `false` otherwise.

### `setReleaseItems`

Replaces the entire item set of a draft release in one shot. Every item is validated first, then the old items are cleared and the new set is inserted in a single transaction. Duplicate roots are rejected with `RELEASE_DUPLICATE_ROOT`. Fails with `RELEASE_NOT_FOUND`, `RELEASE_NOT_DRAFT`, `ROOT_NOT_FOUND`, or `BRANCH_NOT_FOUND`.

<APIMethod method="POST" path="/releases/setReleaseItems" resource="release" operation="update" returns="{ items }" params={{
  releaseId: { type: 'string', required: true, description: 'The draft release.' },
  items: { type: '{ rootId: string; branchId: string }[]', required: true, description: 'The complete new member list. Replaces all existing items; roots must be unique.' },
}} />

### `getRelease`

Reads a release and its items. Fails with `RELEASE_NOT_FOUND`.

<APIMethod method="GET" path="/releases/getRelease" resource="release" operation="read" returns="{ release, items }" params={{
  releaseId: { type: 'string', required: true, description: 'The release to fetch.' },
}} />

### `listReleases`

Lists releases, newest first, with an optional status filter. All query fields are optional.

<APIMethod method="GET" path="/releases/listReleases" resource="release" operation="read" returns="{ releases, total, hasMore }" params={{
  status: { type: "'draft' | 'published'", description: 'Filter by release status.' },
  limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
  offset: { type: 'number', default: '0', description: 'Rows to skip.' },
}} />

### `publishRelease`

Publishes every item in the release atomically. Runs the same per-root publish machinery as `pages.publishBranch` for each item inside one database transaction: if any item fails (for example an unapproved branch under a policy that requires approval), the whole set rolls back and nothing goes live. On success the release flips to `published`. Fails with `RELEASE_NOT_FOUND`, `RELEASE_NOT_DRAFT`, `RELEASE_EMPTY`, `ROOT_NOT_FOUND`, `BRANCH_NOT_FOUND`, or `PUBLICATION_APPROVAL_REQUIRED`.

<APIMethod method="POST" path="/releases/publishRelease" resource="release" operation="update" returns="{ release, publications }" params={{
  releaseId: { type: 'string', required: true, description: 'The draft release to publish.' },
  publishedBy: { type: 'string', description: 'Fallback actor id, used only when the request has no session user (the request user takes precedence).' },
}} />

```ts
const { release, publications } = await cms.api.releases.publishRelease({
  body: { releaseId: 'rel_abc123' },
});
```

The updated `release` has `status: 'published'` and a set `publishedAt`; `publications` holds one publication per item.
