---
title: Publications API
description: Publish, unpublish, schedule, and read published content.
---

Publications control what content is publicly live. Every method lives at `cms.api.<collection>.<method>` (use your collection name, e.g. `cms.api.pages`) and mirrors on the client as `client.<collection>.<method>` with identical types.

Publishing points a publication at the branch's existing head commit rather than creating a new one, so unlike the entry and block mutation APIs these methods do not return a `commit` envelope.

## Publishing

### Publish a Branch [#publishbranch]

Publish a branch, making its head commit the version your readers see live. You get back the resulting `publication` (publishing points at the existing head commit, so there is no new `commit`). Fails with `PUBLICATION_APPROVAL_REQUIRED` if the branch has open approval requests that are not all approved.

<APIMethod
  method="POST"
  path="/{collection}/publishBranch"
  fn="publishBranch"
  resource="publication"
  operation="create"
  args={`{
  body: {
    rootId: 'root_home', // required
    branchId: 'br_main', // required
  },
}`}
  returns={{
    publication: { type: 'Publication', description: 'The publication: `{ rootId, branchId, commitId, publishedBy, publishedAt, branchName }`.' },
  }}
  params={{
    rootId: { type: 'string', required: true, description: 'The root to publish.' },
    branchId: { type: 'string', required: true, description: 'The branch whose head commit is published.' },
    publishedBy: { type: 'string', description: 'Actor override; defaults to the current user.' },
  }}
/>

The returned `publication` carries `rootId`, `branchId`, `commitId`, `publishedBy`, `publishedAt`, and `branchName`.

### Unpublish a Branch [#unpublishbranch]

Take a branch's content offline by removing its publication. You get back which commit was live and when it came down. Fails with `PUBLICATION_NOT_FOUND` when no active publication exists for the root-branch pair.

<APIMethod
  method="POST"
  path="/{collection}/unpublishBranch"
  fn="unpublishBranch"
  resource="publication"
  operation="delete"
  args={`{
  body: {
    rootId: 'root_home', // required
    branchId: 'br_main', // required
  },
}`}
  returns={{
    rootId: { type: 'string', description: 'The root whose publication was removed.' },
    branchId: { type: 'string', description: 'The branch whose publication was removed.' },
    unpublishedCommitId: { type: 'string', description: 'The commit that was live before it was taken offline.' },
    unpublishedAt: { type: 'Date', description: 'When the content was taken offline.' },
  }}
  params={{
    rootId: { type: 'string', required: true, description: 'The root whose publication to remove.' },
    branchId: { type: 'string', required: true, description: 'The branch whose publication to remove.' },
  }}
/>

## Scheduling

### Schedule a Publish [#schedulepublication]

Queue a branch to publish itself at a future time. Nothing goes live until the cron-driven `admin.runScheduled` processes the due row; the root (in scope) and branch are validated up front, so you catch bad ids now rather than at run time.

<APIMethod
  method="POST"
  path="/{collection}/schedulePublication"
  fn="schedulePublication"
  resource="publication"
  operation="create"
  args={`{
  body: {
    rootId: 'root_home', // required
    branchId: 'br_main', // required
    scheduledAt: '2026-01-01T00:00:00Z', // required
  },
}`}
  returns={{
    scheduled: { type: 'ScheduledPublication', description: "The queued row: `{ id, rootId, branchId, action: 'publish', scheduledAt, processedAt }` (`processedAt` is null until the cron runs it)." },
  }}
  params={{
    rootId: { type: 'string', required: true, description: 'The root to publish when due.' },
    branchId: { type: 'string', required: true, description: 'The branch whose head commit is published when due.' },
    scheduledAt: { type: 'Date', required: true, description: 'When the publish becomes due (ISO string or Date).' },
  }}
/>

The returned `scheduled` row carries `id`, `rootId`, `branchId`, `action: 'publish'`, `scheduledAt`, and `processedAt` (null until run).

### Schedule an Unpublish [#scheduleunpublish]

Queue a branch's content to go offline at a future time. The content is taken down when `admin.runScheduled` processes the due row, so reach for this to expire content on a schedule.

<APIMethod
  method="POST"
  path="/{collection}/scheduleUnpublish"
  fn="scheduleUnpublish"
  resource="publication"
  operation="delete"
  args={`{
  body: {
    rootId: 'root_home', // required
    branchId: 'br_main', // required
    scheduledAt: '2026-02-01T00:00:00Z', // required
  },
}`}
  returns={{
    scheduled: { type: 'ScheduledPublication', description: "The queued row, same shape as `schedulePublication` but with `action: 'unpublish'`." },
  }}
  params={{
    rootId: { type: 'string', required: true, description: 'The root to unpublish when due.' },
    branchId: { type: 'string', required: true, description: 'The branch whose publication is removed when due.' },
    scheduledAt: { type: 'Date', required: true, description: 'When the unpublish becomes due (ISO string or Date).' },
  }}
/>

The returned `scheduled` row is identical in shape to `schedulePublication`, with `action: 'unpublish'`.

## Reading

### Read Published Content [#getpublishedcontent]

Fetch the live, published content for an entry, looked up by `rootId`, `slug`, or `path` (pass at least one). References are resolved inline and variables substituted unless you set `raw`. It runs the full auth chain (so plugin scope stays enforced) but is conventionally anonymous-readable.

<APIMethod
  method="GET"
  path="/{collection}/getPublishedContent"
  fn="getPublishedContent"
  resource="publishedContent"
  operation="read"
  anonymousRead
  args={`{
  query: { slug: 'welcome' }, // one of rootId, slug, or path required
}`}
  returns={{
    rootId: { type: 'string', description: 'The resolved entry id.' },
    collection: { type: 'string', description: 'The collection the entry belongs to.' },
    variants: { type: '{ branchId, branchName, commitId, publishedAt, publishedBy, tree }[]', description: 'One entry per published branch, each with a fully resolved block `tree`. A single-element array when you pass `branchName`.' },
    abTest: { type: '{ testId, trafficPercentage, controlBranchId }', optional: true, description: 'Present only when the entry has a running page-level A/B test with at least two published variant branches and a published control.' },
    ancestors: { type: '{ rootId, slug }[]', optional: true, description: "The entry's ancestor chain. Present only for nested-slug collections." },
  }}
  params={{
    rootId: { type: 'string', description: 'Fetch this root directly. One of rootId, slug, or path is required.' },
    slug: { type: 'string', description: 'Resolve a root by slug; must be unique within the active scope.' },
    path: { type: 'string', description: 'Resolve a root by path (for nested slugs).' },
    raw: { type: 'boolean', description: 'If true, skip variable substitution and link-path resolution.' },
    branchName: { type: 'string', description: 'Resolve only this published branch (returned as a length-1 variants array). When omitted, all published branches are returned.' },
  }}
/>

Each `variants` item carries `branchId`, `branchName`, `commitId`, `publishedAt`, `publishedBy`, and a resolved block `tree`. `ancestors` is present only for nested-slug collections.

### List Publications [#listpublications]

List the publications in a collection, so you can see what is currently live and when it went out. Filter by root, branch, or date range. Publications of soft-deleted roots are excluded.

<APIMethod
  method="GET"
  path="/{collection}/listPublications"
  fn="listPublications"
  resource="publication"
  operation="read"
  args={`{
  query: { limit: 20, rootId: 'root_home' },
}`}
  returns={{
    publications: { type: 'Publication[]', description: 'The publications on this page. Each item: `{ rootId, branchId, commitId, publishedBy, publishedAt, branchName, rootProperties }`, plus `publishedByUser` when user enrichment is enabled.' },
    total: { type: 'number', description: 'Total publications matching the filter, ignoring limit/offset.' },
    hasMore: { type: 'boolean', description: 'Whether more publications exist after this page.' },
  }}
  params={{
    limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
    offset: { type: 'number', default: '0', description: 'Rows to skip.' },
    rootId: { type: 'string', description: 'Filter to publications of a specific root.' },
    branchId: { type: 'string', description: 'Filter to publications of a specific branch.' },
    publishedAfter: { type: 'Date', description: 'Only publications on or after this date.' },
    publishedBefore: { type: 'Date', description: 'Only publications on or before this date.' },
    sortDirection: { type: "'asc' | 'desc'", default: "'desc'", description: 'Sort order by publish date (newest first by default).' },
  }}
/>

Each `publications` item includes `rootId`, `branchId`, `commitId`, `publishedBy`, `publishedAt`, `branchName`, `rootProperties`, and (when user enrichment is enabled) `publishedByUser`.
