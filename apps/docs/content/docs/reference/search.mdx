---
title: Search
description: Full-text search across CMS entities, via cms.api.search.
---

Full-text search runs over a maintained index spanning seven entity types: `root`, `comment`, `mergeRequest`, `variable`, `template`, `asset`, and `notification`. The method lives at `cms.api.search.query` and mirrors on the [client](/docs/reference/client-api) as `client.search.query` with identical types.

Results honour the caller's read boundary: rows are returned only when their underlying entity is visible under the active plugin scope, and `notification` rows surface only to their recipient.

## Methods

### Search Across Entities [#query]

Run one full-text query across every indexed entity and get back matches ranked by relevance. Narrow the search by entity type, collection, or entry, and use each result's `highlight` string (with `<mark>` around the matched terms) to show users exactly where they matched.

<APIMethod
  method="GET"
  path="/search/query"
  fn="query"
  collection="search"
  resource="search"
  operation="read"
  args={`{
  query: {
    search: 'homepage', // required
    entityTypes: ['root', 'variable'],
    limit: 10,
  },
}`}
  returns={{
    results: { type: 'SearchResult[]', description: 'The matches on this page, ranked by relevance (highest `rank` first). See the shape below.' },
    total: { type: 'number', description: 'Total number of matches across all pages, ignoring limit/offset.' },
    hasMore: { type: 'boolean', description: 'Whether more matches exist after this page.' },
  }}
  params={{
  search: { type: 'string', required: true, description: 'Search term. Parsed as a websearch query.' },
  entityTypes: { type: "('root' | 'comment' | 'mergeRequest' | 'variable' | 'template' | 'asset' | 'notification')[]", description: 'Restrict to these entity types. Also accepts a comma-separated string.' },
  collection: { type: 'string', description: 'Restrict to a single collection.' },
  rootId: { type: 'string', description: 'Restrict to a single entry.' },
  limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
  offset: { type: 'number', default: '0', description: 'Rows to skip.' },
}} />

Each result has `entityType`, `entityId`, optional `collection` / `rootId` / `title` / `snippet` / `meta`, a `rank` (relevance), and a `highlight` string with `<mark>` around the matched terms.

## Rebuilding the index

`cms.api.admin.reindexSearch` rebuilds the whole index. See the [Server API](/docs/reference/server-api).
