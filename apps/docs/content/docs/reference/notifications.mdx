---
title: Notifications
description: The per-user inbox, via cms.api.notifications.
---

Notifications are the per-user inbox. The CMS raises them on @mentions in comments, approval decisions, merge-request activity, and publishing. Methods live under `cms.api.notifications` and mirror on the [client](/docs/reference/client-api) as `client.notifications.<method>` with identical types.

These endpoints operate on the recipient's inbox, not on content commits, so no method returns a `commit` envelope. Every endpoint scopes to the authenticated user: reads and mutations only ever touch the current user's own notifications, and acting on another user's notification fails with `NOTIFICATION_RECIPIENT_MISMATCH`.

<Callout type="info">
  The whole `notifications` namespace is omitted when the CMS is configured with `notifications: false`.
</Callout>

## Methods

### List Notifications [#list]

Fetch a page of your notifications (newest first, archived ones excluded) so you can render an inbox. Filter by type, collection, or read status, or leave every query field off to pull the latest across the board.

<APIMethod
  method="GET"
  path="/notifications/list"
  fn="list"
  collection="notifications"
  resource="notification"
  operation="read"
  args={`{
  query: { unreadOnly: true, limit: 10 },
}`}
  returns={{
    notifications: { type: 'NotificationListItem[]', description: 'This page of notifications, newest first. Each carries id, recipientId, actorId, type, title, body, resourceType, resourceId, collection, meta, readAt, and createdAt.' },
    total: { type: 'number', description: 'Total matching notifications across all pages, ignoring limit/offset.' },
    hasMore: { type: 'boolean', description: 'Whether more notifications exist after this page.' },
    unreadCount: { type: 'number', description: 'Count of all your unread notifications, independent of the current page or filters.' },
  }}
  params={{
    type: { type: 'NotificationType', description: 'Filter by notification type (see Types below for the full set).' },
    unreadOnly: { type: 'boolean', description: 'When true, returns only unread notifications.' },
    collection: { type: 'string', description: 'Filter to notifications about one collection.' },
    limit: { type: 'number', default: '20', description: 'Page size, 1 to 100.' },
    offset: { type: 'number', default: '0', description: 'Rows to skip.' },
  }}
/>

`unreadCount` is the count of all unread notifications for the user, independent of the current page or filters. Each item carries `id`, `recipientId`, `actorId`, `type`, `title`, `body`, `resourceType`, `resourceId`, `collection`, `meta`, `readAt`, and `createdAt`. Pass the transport-level `withUser: true` flag to also include `actorUser` (the acting user, limited to your `user` config's `exposeColumns` allowlist) on each item.

### Mark Notifications Read [#marknotificationsread]

Mark a notification as read once you've seen it. Pass a `notificationId` to clear a single one, or omit it entirely to mark your whole unread inbox as read in one call. You get back how many were actually flipped.

<APIMethod
  method="POST"
  path="/notifications/markNotificationsRead"
  fn="markNotificationsRead"
  collection="notifications"
  resource="notification"
  operation="update"
  args={`{
  body: { notificationId: 'notif_8fd21c' }, // omit body to mark all unread as read
}`}
  returns={{
    markedCount: { type: 'number', description: 'How many notifications this call flipped to read.' },
  }}
  params={{
    notificationId: { type: 'string', description: 'Notification to mark read. Omit to mark all unread notifications read.' },
  }}
/>

### Mark Notifications Unread [#marknotificationsunread]

Flag a notification as unread so it resurfaces for later. Pass a `notificationId` to reopen one, or omit it to mark all of your read notifications unread. You get back how many were flipped.

<APIMethod
  method="POST"
  path="/notifications/markNotificationsUnread"
  fn="markNotificationsUnread"
  collection="notifications"
  resource="notification"
  operation="update"
  args={`{
  body: { notificationId: 'notif_8fd21c' }, // omit body to mark all read as unread
}`}
  returns={{
    markedCount: { type: 'number', description: 'How many notifications this call flipped to unread.' },
  }}
  params={{
    notificationId: { type: 'string', description: 'Notification to mark unread. Omit to mark all read notifications unread.' },
  }}
/>

### Archive a Notification [#archivenotification]

Archive a notification to drop it from your active inbox, so it stops showing up in `list`. Use it to clear out items you're done with without losing the underlying record.

<APIMethod
  method="POST"
  path="/notifications/archiveNotification"
  fn="archiveNotification"
  collection="notifications"
  resource="notification"
  operation="delete"
  args={`{
  body: { notificationId: 'notif_8fd21c' }, // required
}`}
  returns={{
    notificationId: { type: 'string', description: 'The id of the notification that was archived.' },
  }}
  params={{
    notificationId: { type: 'string', required: true, description: 'The notification to archive.' },
  }}
/>

## Types

`type` is one of: `mention`, `comment`, `threadResolved`, `threadReopened`, `approvalRequested`, `approvalApproved`, `approvalRejected`, `mergeRequestOpened`, `mergeRequestMerged`, `mergeRequestClosed`, `mergeRequestReopened`, `published`, `custom`.
