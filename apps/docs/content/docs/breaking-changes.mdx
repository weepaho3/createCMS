Every consumer-visible break in `@createcms/core`, newest release first, with the
migration for each one. This is the single place that answers **"what broke since
version X?"** without reading diffs.

The complete release notes (features, fixes, internals) live in the
[changelog](/docs/changelog). This file carries **only** the breaks.

createCMS is pre-1.0, so **minor is the breaking channel** — see
[Versioning](https://github.com/weepaho3/createCMS/blob/main/CONTRIBUTING.md#versioning). Breaking changes are applied cleanly:
no compat shims, no aliases. Pin an exact version.

> **How the pre-0.7 entries were produced.** They were reconstructed by hand from
> the released changesets and diffs of each tag, because no commit in the history
> up to 0.6.0 carried a marker — `git log --pretty=%s | grep -c '!'` and
> `git log --pretty=%B | grep -c "BREAKING CHANGE"` both returned `0` across all
> 223 commits. From now on every break is marked at commit time
> ([Commit conventions](https://github.com/weepaho3/createCMS/blob/main/CONTRIBUTING.md#commit-conventions)) and appended here in
> the same PR that ships it, so this file is maintained forward rather than
> re-derived. The reconstructed sections are complete with respect to the shipped
> changesets; a break that was never written down in a changeset would not appear
> here.

## Unreleased

- **Browser uploads are a presign/complete protocol.** `createSignedUpload`
  no longer creates rows: it returns
  `{ uploads: [{ id, objectKey, url, signedUrl, headers, token }], expiresAt }`
  (no `slug`). After the PUT, the browser calls
  `completeUpload({ uploads: [{ token }] })`, which verifies the landed
  object (length, content type, magic bytes of a declared image) and then
  creates the row; the core client's `useUploadAssets` / `uploadState` do
  this, and an entry is `success` only once `completeUpload` returns it.
  New browser uploads are stored at the object key `<id>/<slug>` (the public
  `url` becomes `<publicUrl>/<id>/<slug>`); existing rows keep their keys.
  `createSignedReplace` returns a `token` and its object key is
  `<fresh id>/<slug>`; `commitReplace` takes `{ token }` only (the
  `assetId`, `objectKey`, `slug`, `mimeType`, `size` body is gone) and
  throws `UPLOAD_NOT_FOUND` instead of `UPLOAD_FAILED` when the PUT never
  landed. New error codes `UPLOAD_TOKEN_INVALID` (403) and
  `UPLOAD_NOT_FOUND` (404); new optional `media.uploadSecret`. A PUT that is
  never completed leaves an object in the bucket but no row.
  → **Migration:** callers of the raw protocol read `uploads` instead of
  `assets`, PUT, then call `completeUpload` with the tokens and read the
  asset (including its `slug`) from its response; `commitReplace` callers
  pass `{ token: signed.token }`. Set `media.uploadSecret` when the S3
  credentials rotate (STS). The React hooks need no change.

- **Releases are now scoped by the multi-tenant plugin.** `releases.ts`
  reads/writes (`createRelease`, `getRelease`, `listReleases`, `addToRelease`,
  `removeFromRelease`, `setReleaseItems`, `publishRelease`) all apply the
  active plugin scope, matching every other first-class table (roots, assets,
  folders, redirects, templates, variables). Under the multi-tenant plugin, a
  tenant can no longer list, read, or mutate another tenant's releases, or add
  another tenant's root to its own release.
  → **Migration:** with the multiTenant plugin, run `createcms generate` and
  apply the migration that adds `releases.tenant_slug` (NOT NULL). Existing
  release rows need a `tenant_slug` backfill before the NOT NULL constraint can
  be applied. Single-tenant deployments are unaffected — no predicate is added.

- **`@createcms/react`: `Canvas.Root` requires `components` and renders the
  store tree.** Pass a block map (the same object `createBlocksMap` returns
  is accepted via `_components`). `children` are no longer the document;
  they render after the tree (overlay). `surface="frame"` throws.
  → **Migration:** `<Canvas.Root components={pageBlocks} />` under
  `Editor.Root`; move previous children that were the page markup into the
  map.

- **`BlockComponentProps` gains a required `edit` prop and its `properties`
  is no longer `| undefined`.** Every block component the renderer calls now
  receives `edit` (`{ active, block, field }`, plain data — `NO_EDIT` outside
  an editor, anchors with `edit="preview"`). Components that ignore `edit`
  keep compiling. `properties` is always an object at runtime and is typed
  that way now.
  → **Migration:** code that renders a block component itself (tests,
  stories, custom canvases) passes `edit={NO_EDIT}` (from
  `@createcms/core/react/blocks`); drop `properties?.` optional chaining if
  you like — it still compiles.

- **`@createcms/react`: `useChildren(parentId)` returns child refs instead of
  ids.** Each entry is `{ id, type, index }` (the factory's `useChildren`
  narrows `type` to the schema's block types), so a row can render its label
  and position without a second hook. The array keeps its identity until ids
  or types change.
  → **Migration:** replace `useChildren(id).map((childId) => ...)` with
  `useChildren(id).map((child) => ... child.id ...)`; nothing else changes.

- **`media.useUploadAssets()` is a byte-accurate ledger.** `totalProgress`
  (0 to 100) is replaced by `progress: { loaded, total, fraction }` with
  `fraction` 0 to 1, summed over bytes rather than averaged over files.
  `isAborted` is removed. Per-file `status` ends in `success` (was `done`),
  `error`, or `aborted` (was `error` with the message `Upload aborted.`);
  `error` is `{ code, message }` instead of a string. Each entry carries
  `id`, `file`, `size`, `type`, `loaded`, and `total`, and `progress` is
  0 to 1. `files` accumulates across `upload()` calls until `reset()`, which
  drops finished entries only. `upload()` resolves with that call's entries,
  accepts `concurrency` (default 4) and `signal`, and PUTs at most
  `concurrency` files at once. `client.media.uploadState` (vanilla) exposes
  the same shape.
  → **Migration:** read `progress.fraction * 100` instead of
  `totalProgress`; match `status === 'success'` instead of `'done'`; treat
  `status === 'aborted'` as cancelled rather than failed; read the new
  asset from the array `upload()` resolves with (or from `files` by `id`)
  and call `reset()` to clear finished rows.

- **`@createcms/react`: `CmsMediaUploadState` and `CmsMediaUploadFileState`
  mirror the new core shape.** `isAborted` and `totalProgress` are gone,
  `progress` is `CmsMediaUploadProgress`, `status` is `CmsMediaUploadStatus`
  (`success` instead of `done`, plus `aborted`), `error` on an entry is
  `{ code, message }`, and `upload` returns `Promise<CmsMediaUploadFileState[]>`.
  → **Migration:** update fakes and idle states to
  `{ isUploading, files: [], progress: { loaded: 0, total: 0, fraction: 0 }, error, upload: async () => [], abort, reset }`
  and any UI that read `totalProgress` or `status === 'done'`.

- **Asset slugs are unique per scope, not globally.** The core unique index
  `assets_slug_unique` becomes the non-unique `assets_slug_idx`; slug
  generation already probes within the caller's scope, and the multi-tenant
  plugin keeps its `(tenant_slug, slug)` unique. Two tenants can now both own
  `hero.jpg`. Server-side `uploadAssets` and `replaceAsset` store objects at
  `<id>/<slug>` (previously the slug verbatim), like browser uploads, so equal
  slugs never share an object; existing rows keep their keys.
  → **Migration:** run `createcms generate` and apply the migration
  (`DROP INDEX cms.assets_slug_unique; CREATE INDEX assets_slug_idx ON
cms.assets (slug);`). Code that derived an object key from a slug reads
  `objectKey` from the asset instead.

- **`archiveAssets` skips assets that may be referenced from rich text.**
  With the new `media.guardRichTextReferences` (default `true`), an asset
  whose id appears inside a longer string of any block version (rich text
  HTML, stringified JSON) is skipped instead of archived, and pruning never
  reclaims it. The response gains `skippedReasons`
  (`in_use` | `richtext_suspect`).
  → **Migration:** pass `force: true` to archive such assets anyway, or set
  `media.guardRichTextReferences: false` once rich text references are
  tracked elsewhere.

- **Publish discovery is scoped to the publishing request.** Publishing,
  unpublishing, release publishes and scheduled passes only change the status
  of assets inside the active `scope.assets`, and only publications of roots
  in scope keep an asset public. Content in one tenant that names another
  tenant's asset id no longer flips that asset's status.
  → **Migration:** none for single-tenant setups.

- **The media optimizer never blocks or throws.** `optimizeImage` resolves
  with the input file and a `warning` instead of rejecting, and only
  re-encodes JPEG, PNG and WebP: GIF, SVG, ICO, BMP, AVIF, TIFF, HEIC/HEIF,
  animated WebP/APNG and files carrying IPTC `DigitalSourceType` or a C2PA
  manifest are uploaded byte-identical. A result larger than
  `keepIfSmallerRatio` (default 0.9) of the input is discarded unless the
  image was downscaled. The default quality is 82 (was 80). `OptimizeResult`
  gains `bytesBefore`, `bytesAfter` and `warning`; `OptimizeState` (from
  `useOptimize`) loses `error`. `@jsquash/webp` is no longer an optional peer
  and is never imported by the plugin.
  → **Migration:** read `result.warning` instead of catching; drop
  `state.error`. For WebP in Safari, install `@jsquash/webp` and pass
  `webpEncoder: () => import('@jsquash/webp/encode')` to
  `mediaOptimizeClient`.

- **Upload ledger entries carry `optimize` instead of `optimized` and
  `originalVariantId`.** `CMSMediaUploadFileState.optimize` is
  `{ optimized, bytesBefore, bytesAfter, warnings }` when the media-optimize
  plugin processed the file.
  → **Migration:** read `entry.optimize?.optimized`; `originalVariantId` was
  never set and has no replacement.

- **`@createcms/react`: `CmsMediaUploadFileState` carries `optimize` instead
  of `optimized` and `originalVariantId`**, mirroring the core ledger entry.
  → **Migration:** update fakes that set `optimized` or `originalVariantId`.

- **The upload client signs, uploads and completes each file on its own.**
  `useUploadAssets().upload(files)` calls `createSignedUpload` with one file
  when a pool slot takes it and `completeUpload` right after that file's PUT,
  retries transient failures and re-signs an expired PUT once. A signing
  failure now marks only that file `error`, and the ledger's `error` is the
  string `Some files failed to upload` rather than the thrown
  `CMSClientError`. `maxFiles` therefore limits a single raw
  `createSignedUpload` call, not a client `upload()` call. The default
  `signedUrlExpiresIn` is 300 s (was 120 s).
  → **Migration:** read per-file `entry.error` instead of the ledger's
  `error` object. Enforce a per-batch file limit in the UI if you relied on
  `TOO_MANY_FILES` from the client.

- **`@createcms/react`: `/media` reads its texts from a messages catalog.**
  `Media.Root` takes `messages` and `locale`; `Media.Crumb` for the root
  defaults to `Library` (was `Root`), and `Media.UploadProgress` announces
  the translated error code instead of the server message. In the docs
  registry, `MEDIA_LABELS`, `MEDIA_PICKER_LABELS` and `formatBytes` are
  removed.
  → **Migration:** pass translated texts as `messages` (see
  `defaultMediaMessages` for the keys) instead of editing `MEDIA_LABELS`;
  pass `children` to `Media.Crumb` to keep a custom root label.

- **Objects live under `pub/` or `prv/` and move with the asset status.**
  The new `media.visibility` defaults to `'prefix'`: new objects are keyed
  `{t/<tenant>/}{pub|prv}/<id>/<slug>`, and a status change (publish,
  unpublish, `updateAssetsStatus`) copies the object and its variants to the
  other prefix, updates `objectKey` and deletes the old object. No ACL header
  is sent, so the bucket must grant public reads on `pub/*` through a bucket
  policy or CDN. `createCMS` throws when the storage lacks the `copy`
  capability. Existing objects keep their keys until their next status
  change.
  → **Migration:** add a bucket policy for `pub/*` (see Media: Bucket setup)
  and run `createcms storage check`, or set `media.visibility: 'legacy'` to
  keep the previous key layout.

- **`media.acl` defaults to `false`.** `x-amz-acl: public-read` is sent only
  with `acl: 'public-read'`, `visibility: 'legacy'` and a storage that
  reports `objectAcl`; otherwise the setting is ignored with a warning.
  → **Migration:** buckets that relied on per-object ACLs set
  `visibility: 'legacy'` and `acl: 'public-read'`, or move to a bucket
  policy.

- **Asset `url` is `null` for private assets; `deliveryUrl` is new.**
  `listAssets`, `getAssets`, the upload and replace responses return the
  direct object URL only for public assets and add `deliveryUrl`, the gate
  path. The gate serves private assets to callers the auth middleware
  accepts for `media` / `read` (signed GET, at most 300 s,
  `Cache-Control: private, no-store`); with a scoping plugin, ids outside the
  caller's scope answer `ASSET_NOT_FOUND`. The gate now carries
  `permissionResource: 'media'`, and the middleware runs for private assets
  and, under a scoping plugin, for every gate request.
  → **Migration:** render `deliveryUrl` instead of `url`. Make sure the auth
  middleware does not throw for anonymous image requests unless private
  assets should stay unreachable for them.

- **`StorageCapabilities` follows the provider capability model.**
  `signedUpload` is now `signedPut` and `signedUrl` is `signedGet`; new
  required flags are `signedPost`, `copy`, `list`, `deleteMany`,
  `multipart`, `objectAcl`, `conditionalPut`, `checksum`,
  `corsConfigurable` and `lifecycle`. `head` may return `cacheControl`;
  `put`, `signPut` and `signGet` take more options; `copy`, `deleteMany` and
  `list` are optional methods.
  → **Migration:** custom adapters spread `providerCapabilities.generic` and
  override what differs, and implement `copy` for `visibility: 'prefix'`.

- **`@createcms/react`: `CmsAssetListItem.url` is `string | null` and
  `deliveryUrl` is required.** `Media.Thumbnail` defaults to `deliveryUrl`.
  → **Migration:** fakes add `deliveryUrl`; code reading `asset.url` handles
  `null`.

- **Media data model: new asset and folder columns.** `assets` gains
  `width`, `height`, `original_name`, `sha256`, `provenance`
  (`asset_provenance` enum), `variant_key`, `revision_of`, `metadata`
  (jsonb) and partial indexes; `size` becomes `bigint` (a table rewrite:
  plan a maintenance window on large tables). `asset_folders` gains `path`,
  `depth`, `updated_at` and `archived_at`; its parent foreign key changes
  from `cascade` to `restrict`, and the `(parent_id, name)` unique index
  only covers live folders. The multi-tenant plugin adds a per-tenant unique
  index on root folder names and `(tenant_slug, sha256)`.
  → **Migration:** under the multi-tenant plugin, rename duplicate root
  folder names per tenant first (the new index rejects them). Run
  `createcms generate`, apply the migration, then call
  `cms.api.admin.runMediaBackfill` until its `cursor` is `null` to fill
  original names, variant keys, dimensions and folder paths. Variants whose
  slug follows no known scheme become standalone assets (listed in the
  report).

- **Folders are deleted into the trash, by mode.** `deleteFolder` takes
  `mode` (`empty-only` default, `move-to-parent`, `archive-contents`) and
  `dryRun`, sets `archivedAt` instead of deleting the row, and returns
  `{ folderId, folders, assets, assetsInUse, skipped }`. Assets keep their
  `folderId` when archived with their folder. `createFolder`, `moveFolder`
  and the new `renameFolder` reject a name a live sibling already has
  (`FOLDER_NAME_TAKEN`), root folders included. Uploads into a folder in
  the trash fail with `FOLDER_NOT_FOUND`.
  → **Migration:** read the new `deleteFolder` result; handle
  `FOLDER_NAME_TAKEN` where folders are created or renamed.

- **An `image` property holds `string | AssetRef`.** The value may be a
  bare asset id or `&#123; assetId, alt?, decorative?, caption?, crop?, focal?,
revisionId? }`; the inferred property type is the `ImageValue` union.
  Image elements of a `list` stay ids. `requireAlt` on an image property
  rejects values without `alt` or `decorative: true`.
  → **Migration:** code that reads image properties takes the id with
  `assetIdOf(value)` (from `@createcms/core`); stored values need no change.

- **Downloads use the original file name.** The gate's download
  disposition is `attachment; filename="<ascii>"; filename*=UTF-8''<name>`
  built from `originalName` (falling back to the slug) with RFC 8187
  encoding, instead of `attachment;filename="<slug>"`.
  → **Migration:** none, unless you parse the header.

- **Replaced bytes are kept as revisions.** A replace writes the
  superseded object as a row with `revisionOf` set, and pruning keeps the
  ten newest revisions per asset (and every revision pinned in content), so
  superseded objects are no longer reclaimed after the trash window alone.
  → **Migration:** none; storage use grows by up to ten versions per
  replaced asset.

- **`@createcms/react`: the editor's `image` field value is `ImageValue`.**
  `FieldValueMap['image']` is `string | AssetRef`, client validation accepts
  an `AssetRef`, and `CmsAssetListItem` gains optional `originalName`,
  `width`, `height`, `provenance`, `metadata` and `variants`. `MediaClient`
  gains optional methods for the new media endpoints.
  → **Migration:** custom image field controls read the id from an
  `AssetRef` value; fakes of `MediaClient` need no change.

- **The client upload ledger is an upload queue.** `useUploadAssets()` (and
  the vanilla `client.media.uploadState`) returns one queue per client that
  `upload()` and the new `replace()` share. Entry statuses are `queued`,
  `preparing`, `signing`, `uploading`, `completing`, `retrying`, `paused`,
  `success`, `error` and `aborted` (`pending` is gone). Entries gain `kind`,
  `phase`, `attempt`, `nextRetryAt` and `folderId`; `error` gains
  `retryable`. `progress` gains `bytesPerSecond` and `eta`, and the state
  gains `budget`, `retry`, `pause`, `resume` and `resolveDuplicate`.
  `CMSMediaUploadOptions.concurrency` is removed: the queue runs at most four
  files and six connections across all calls. `abort(id?)` takes an entry id
  and deletes any bytes that already landed (`abortUpload`); an entry whose
  bytes landed still completes. `error` holds the last failing error instead
  of `'Some files failed to upload'`. The vanilla `client.media.replaceState`
  atom is removed, and `useReplaceAsset()` returns
  `{ entries, isReplacing, replace, abort, retry }` over the queue's replace
  entries.
  → **Migration:** match the new statuses (treat `queued` as the old
  `pending`, and `preparing` through `retrying` as in progress); drop
  `concurrency`; replace through `uploadState.get().replace(assetId, file)`
  in the vanilla client; read a replace's outcome from the entry
  `replace()` resolves with instead of `result`/`progress` on the hook.

- **Pruning deletes orphaned upload objects.** When the storage can list
  keys, `runPruning` deletes objects whose key has the CMS layout
  (`[t/<tenant>/][pub/|prv/]ast_<id>/...`), that no asset row points at,
  and that are older than `signedUrlExpiresIn` plus one hour.
  → **Migration:** none, unless you write objects under CMS-shaped keys
  yourself; keep those outside that layout.

- **`@createcms/react`: the upload types mirror the upload queue.**
  `CmsMediaUploadState`, `CmsMediaUploadFileState`, `CmsMediaUploadStatus`
  and `CmsMediaUploadProgress` follow the core queue shape above; the
  `/media` upload status messages are keyed by the new statuses.
  → **Migration:** update fakes and idle states with `budget`, `replace`,
  `retry`, `pause`, `resume`, `resolveDuplicate`, and
  `progress: { loaded: 0, total: 0, fraction: 0, bytesPerSecond: null, eta: null }`;
  custom message catalogs add `upload.status` texts for every status.

- **The media-optimize plugin is a rendition pipeline with a new config.**
  `compress`, `resize`, `convert` and `webpEncoder` are gone, and so are
  `optimizeImage`, `optimizeFiles`, `optimizeForUpload` and the
  `OptimizationConfig` type (no longer exported from `@createcms/core`). The
  plugin now keeps the original (GPS removed), uploads WebP renditions at
  320, 640, 1280 and 1920 px as variants, and takes `original`,
  `renditions`, `quality`, `avif`, `stripGps`, `keepCopyright`,
  `placeholder`, `concurrency`, `timeoutMsPerMegapixel`, `provenance`,
  `codecs`, `pdf` and `worker`. `useOptimize` resolves to `OptimizeOutput`
  per file. A custom `UploadOptimizer` implements `process(file)` returning
  `{ file, renditions, hints?, info? }` instead of `optimize(files)`.
  → **Migration:** replace `mediaOptimizeClient({ convert: { format: 'webp' }, webpEncoder })`
  with `mediaOptimizeClient({ codecs: { webp: () => import('@jsquash/webp/encode') } })`;
  a fixed `resize.maxSize` becomes `original: 'master'` with
  `masterLongEdge`; read results from `OptimizeOutput` instead of
  `OptimizeResult`.

- **The asset endpoint serves renditions by snapped width.** `?w=` snaps up
  to the next of `renditionWidths` (default 320, 640, 1280, 1920) and a
  larger `w` answers 400 `RENDITION_WIDTH_UNSUPPORTED`; `?format` without
  `w` asks for the largest width, and `w` without `format` for WebP. A
  missing rendition falls back to the next larger one, then to the
  original; `strict=true` answers 404 `RENDITION_NOT_FOUND` instead.
  → **Migration:** request widths from the ladder (or set
  `renditionWidths`), and include `strict` in CDN cache keys if you use it.

- **Upload queue entries include renditions.** With the media-optimize
  plugin, a finished upload stays `completing` (phase `renditions`) until
  its rendition entries (`kind: 'rendition'`, `parentId`, `variantKey`)
  finished; the queue state gains `regenerateRenditions(assetId)`.
  `@createcms/react` mirrors this in `CmsMediaUploadFileState` and
  `CmsMediaUploadState`, and `Media.UploadList` lists parents only.
  → **Migration:** fakes of the upload state add `regenerateRenditions`;
  code that iterates `files` skips entries with a `parentId` if it lists
  uploads.

- **A declared AVIF must be AVIF.** `completeUpload` and the server upload
  paths now recognize AVIF bytes, so a file declared `image/avif` whose
  bytes are not AVIF is rejected with `INVALID_FILE_TYPE`.
  → **Migration:** none for valid files.

- **`content_usages` carries paths and alt-text state.** The usage index
  gains the columns `path`, `matched_by`, `alt_state` and `revision_id`, a
  unique index on version, target and path, and indexes for root lookups and
  missing alt text; `branches` gains an index on `head_commit_id`. Asset
  usages are now indexed per occurrence by the property schema (lists, alt
  text, revision pins) and include asset URLs in text.
  → **Migration:** regenerate the schema (`generate`), run the migration,
  then call `admin.runUsageBackfill` until its `cursor` is `null` so
  existing block versions are re-indexed.

- **`getAssetUsages` returns roots grouped and paginated.** The query takes
  `assetId`, `scope` (`live` by default, `published`, `history`),
  `branchId`, `collection`, `missingAlt`, `cursor` and `limit`, and the
  response is `&#123; total: &#123; roots, occurrences, hiddenRoots }, items,
nextCursor }`, each item a root with `title`, `status`, `via` and its
  `occurrences`. The former `pageCount` and `pages` are gone.
  `@createcms/react` types `MediaClient.getAssetUsages` the same way.
  → **Migration:** read `total.roots` instead of `pageCount` and `items`
  instead of `pages`; pass `scope: 'published'` for the former
  published-only answer.

- **`archiveAssets` skips assets in use by any branch head, and `force`
  overrides it.** An asset used by the head of any branch is skipped with
  `in_use` (published content only before), an asset a
  `media.usageSources` entry reports with `external`; `force: true` now
  archives all skipped assets, `in_use` ones included. The response adds
  `usage` and `usedByArchivedRoots`.
  → **Migration:** show `getAssetUsages` before passing `force`; code that
  relied on `force` not touching used assets checks `skippedReasons` first.

- **Pruning keeps assets that any commit uses.** An archived asset is
  reclaimed only when no block version in any commit snapshot uses it
  (history and archived roots included) and no usage source reports it,
  instead of when no live head references it.
  → **Migration:** none; archived assets used by old commits are freed once
  those commits were pruned.

- **`listAssets` lists originals only, and the assets table gets a search
  index.** Variants (renditions) and revisions no longer appear in
  `listAssets`; they are reached through `variants` and `listRevisions`.
  The `assets` table gains the GIN index `assets_search_gin` over the
  weighted file name, description, credit and copyright, used by the new
  `q` parameter. `listAssets` also takes `kinds`, `mime`, `recursive`,
  `visibility`, `provenance`, `uploadedBy`, `createdFrom`, `createdTo`,
  `sizeMin`, `sizeMax`, `widthMin`, `heightMin`, `orientation`,
  `expiringWithinDays`, `archived`, the sorts `updatedAt`, `originalName`
  and `width`, and `includeTotal` (`total` is `null` with `false`).
  → **Migration:** regenerate the schema and run the migration. Code that
  found renditions through `listAssets` reads `variants` of the original.

- **Bulk media endpoints take `assetIds` or `allMatching`.**
  `updateAssetsStatus`, `moveAssets`, `archiveAssets` and `restoreAssets`
  accept `allMatching: { query, except }` (a `listAssets` filter resolved
  on the server, at most 10,000 assets) instead of `assetIds`; `assetIds`
  is no longer required on its own.
  → **Migration:** none for callers passing `assetIds`; typed wrappers of
  the bodies make `assetIds` optional.

- **`@createcms/react`: the media store moved to `/media/core` and works by
  commands.** `createMediaStore` is exported from
  `@createcms/react/media/core` and returns a store with slices
  (`collection`, `selection`, `folders`, `preview`, `detail`, `ui`,
  `mutation`), `dispatch(command)`, typed events (`on`) and registries.
  `MediaLibraryState`, `MediaStoreActions`, `MediaBulkResult`,
  `MediaListStatus`, `MediaMutationState` and `SEARCH_DEBOUNCE_MS` (now in
  core) are gone from `/media`; `useMediaLibrary()` returns
  `&#123; state, dispatch, assets, folders, openFolder, setFilter, setLayout,
refresh }` and `useMediaSelection()` the new `MediaSelection`.
  `MediaContextValue` has `announce` instead of `selection`. The folder
  type is exported as `MediaFolderRecord`.
  → **Migration:** replace `actions.navigate(folder)` with
  `dispatch({ type: 'openFolder', folderId })`, `setSearch` and `setSort`
  with `setFilter({ q })` and `setFilter({ sort })`, `archive`, `move` and
  `setStatus` with the `archive`, `move` and `setVisibility` commands (or
  `Bulk.Action`), and read state from `state.collection`,
  `state.selection` and `state.folders`.

- **`@createcms/react`: `Media.Grid` is an APG grid placed by the layout
  engine.** `Media.Grid` renders `div[role=grid]` with `row` and `gridcell`
  elements instead of `ul[role=listbox]` with `li[role=option]`; cells are
  absolutely positioned from the layout (`minCell`, `gap`, `aspect`, the
  store's `layout` mode) and the grid gets the content height. Clicks
  follow OS conventions (Cmd/Ctrl toggles, Shift selects a range) instead
  of toggling in multiple mode. `Media.Thumbnail` loads the 320 px
  rendition with `alt=""` (the cell is named), not `asset.url` with the
  slug as `alt`.
  → **Migration:** style cells as filling their box (no CSS grid on
  `Media.Grid`), select `[role=gridcell]` instead of `[role=option]`, and
  add `Selection.Checkbox` where users toggled by clicking.

- **`@createcms/react`: `Media.Dropzone` is replaced by the `Intake.*`
  parts.** `Media.Dropzone`, `MediaDropzoneProps`, `MediaDropzoneState`,
  `MediaRejectReason` and `acceptsFile` are gone from `/media`;
  `Intake.Dropzone`, `Intake.Input`, `Intake.FolderInput`, `Intake.Paste`,
  `Intake.Overlay` and `Intake.FolderPrompt` take `IntakeHandlerOptions`
  (`onUploaded` receives upload entries), read folders and accept drops
  while uploading. `acceptsFile` and `validate` are in `/media/core`.
  → **Migration:** use `Intake.Dropzone` with `Intake.Input` inside it;
  read `entry.result` in `onUploaded`.

- **`@createcms/react`: other media parts changed.** `Media.Breadcrumbs`
  passes `{ head, overflow, tail, all }` instead of an array of folders;
  `Media.LoadMore` renders only while a next page exists instead of being
  disabled; `Media.Empty` renders for empty filters too, with
  `data-empty-reason` and the catalog text as default children;
  `Media.UploadList` no longer renders a `role="log"` (`Media.Root` owns the
  live regions and announces uploads); `Media.UploadProgress` reports
  `aria-valuenow` in 10 percent steps. `MediaMessages` gains the `grid`,
  `empty`, `filter`, `intake` and `move` groups and new keys under
  `folder`, `selection`, `bulk`, `upload` and `error`.
  → **Migration:** read `all` (or `head`, `overflow`, `tail`) in
  breadcrumbs; complete full catalogs typed as `MediaMessages` with the new
  keys (a partial `MediaMessagesInput` falls back to English).

- **Media uploads are checked more strictly.** SVG (`image/svg+xml` or a
  `.svg` name) is refused even when `allowedMimeTypes` lists it or a
  wildcard covers it. Every upload is sniffed from its first 4,100 bytes,
  not only images: markup is refused under any type except plain text, and
  image, video, audio and PDF types whose bytes match no or another
  signature answer `INVALID_FILE_TYPE` (previously only PNG, JPEG, GIF,
  WebP and AVIF were checked, and exotic declared image types passed).
  Range reads are required for every upload, not only images. Stored file
  names are normalized and get the extension of their type, so `readme`
  uploaded as a PDF is stored as `readme.pdf` with the slug `readme.pdf`.
  Upload tokens carry the endpoint and host they were signed for; tokens
  signed before the update no longer redeem. State-changing media requests
  that carry cookies from another origin answer `ORIGIN_NOT_ALLOWED` (403).
  Signing is limited to 60 files per actor and minute by default.
  → **Migration:** convert SVG assets to PNG or WebP before uploading;
  finish or restart uploads in flight during the deploy; an admin UI on
  another domain sets `media.allowedOrigins` (or sends
  `x-createcms-media: 1`); raise `media.uploadRateLimit` (or set `0`) for
  bulk importers.

- **`@createcms/react`: the upload parts moved to `Upload.*`.**
  `Media.UploadList`, `Media.UploadItem`, `Media.UploadProgress`,
  `Media.UploadAbort` and `Media.UploadClear` are gone, and so are their
  `MediaUpload*Props` types. They are `Upload.List`, `Upload.Item`,
  `Upload.Progress`, `Upload.Cancel` (cancels the enclosing entry, or every
  upload outside an item) and `Upload.Clear` (now `disabled` while uploads
  run or nothing is listed), with `Upload*Props` types. `MediaMessages`
  gains the `preview`, `detail`, `focal`, `crop`, `imageField`, `replace`
  and `download` groups and new keys under `picker`, `upload` and `error`.
  → **Migration:** rename the parts (`Media.UploadAbort` becomes
  `Upload.Cancel`); complete full catalogs typed as `MediaMessages` with the
  new keys.

**No API breaks.** One behaviour change worth knowing about before you upgrade:

- **Three-way merges auto-resolve more.** Blocks where source and target changed
  _disjoint_ sets of top-level properties now merge automatically (git-style: block

## 0.5.0 — 2026-08-03

- **`media.uploadAssets` and `media.replaceAsset` no longer exist on the client's
  inferred types.** Both take an in-process `buffer: Blob | ArrayBuffer` that cannot
  survive the client's JSON request body, so a browser call type-checked and then
  failed at runtime. They are now marked `scope: 'server'` and the client type
  builder omits them — `client.media.uploadAssets(…)` is a compile error.
  → **Migration:** browser callers use the signed flows —
  `createSignedUpload` for uploads, `createSignedReplace` + `commitReplace` (or the
  `client.media.useReplaceAsset()` hook / the `client.media.replaceState` atom in the
  vanilla client) for replaces. Server-side `cms.api.media.uploadAssets` /
  `replaceAsset` are unchanged and still fully callable.
  This is a **type-level** guard only: the client's request proxy still dispatches
  any method name it is handed, so an `as any` escape hatch reaches the same route
  and fails exactly as before.

- **Upload/replace failures no longer return the S3 provider error to the client.**
  `uploadAssets` and `replaceAsset` used to put the raw provider message on
  `data.cause`, which reached the wire. The full detail is still logged server-side;
  the client-facing error is trimmed to a status code.
  → **Migration:** anything reading `err.data.cause` for storage-error detail must
  read it from your server logs (or your `onAPIError` sink) instead.

## 0.4.0 — 2026-08-02

The release with the largest blast radius for consumers: it changes how the package
is _loaded_, not just what it exposes.

### Packaging and runtime

- **`@createcms/core` is ESM-only.** The CommonJS build is gone: the `main` and
  `module` fields are removed and every `exports` subpath resolves to ESM only.
  → **Migration:** CommonJS projects do **not** need to convert to `import` — Node
  resolves ESM from `require()` natively since 22.12, so `require('@createcms/core')`
  keeps working. Bundlers and tooling that resolved through `main`/`module` need to
  respect the `exports` map.
- **Minimum Node is now 22.12** (`engines.node` was `>=20`). This is the direct
  consequence of dropping the dual build: 22.12 is where `require(esm)` landed.
  → **Migration:** raise your runtime (and CI matrix) to Node ≥ 22.12.
  Dropping the dual build also removed the dual-package hazard — the client layer
  holds module-level state in nanostores atoms, and a graph that loaded both copies
  ended up with two independent stores.
- **The `next` peer range moved from `>=16` to `>=16.2.11`.** Every 16.x below that
  carries nine security advisories, four high (SSRF in Server Actions, an App Router
  middleware/proxy bypass, SSRF via rewrites); createCMS ships a `next/middleware`
  integration, so the exposure is real rather than theoretical.
  → **Migration:** upgrade Next to ≥ 16.2.11. `next` remains an _optional_ peer —
  projects not using Next.js are unaffected.

### API

- **`duplicateBlock` requires `targetParentBlockId`** and is child-duplication only.
  Omitting it used to mint a new top-level root while the endpoint declared only
  `block:create`, so a host granting `block:create` and denying `root:create` could
  be bypassed through duplication. Its return type is no longer a union (`mode` is
  always `'child'`).
  → **Migration:** to duplicate a subtree into a new top-level entry, call
  `duplicateRoot` — same arguments, and it has always been guarded as `root:create`.
  Callers that narrowed the old union return can drop the narrowing.
- **`publishRelease` now declares `publication:create`** (was `release:update`),
  matching `publishBranch`.
  → **Migration:** hosts that grant `release:update` for release curation must also
  grant `publication:create` to allow publishing.
- **`listMentions` no longer accepts a `mentionedUserId` query parameter.** It
  filtered on the caller-supplied value, letting any caller read another user's
  mention inbox; the filter is now derived from the session user.
  → **Migration:** drop the parameter. The endpoint always returns the session
  user's mentions.
- **`ApprovalOutput.branchId` is now `string | null`.** It is `null` for approvals
  whose branch has since been deleted.
  → **Migration:** handle `null` wherever you read `branchId` off an approval.

### Validation (previously-accepted input now throws)

- **`createBlock.position` is `z.number().int().min(0)`.** A negative value used to
  silently insert near the end of the parent's children (it went straight into
  `Array.prototype.splice`) and a fractional value was truncated. The insert index is
  now clamped to the child count.
- **`targetProperties` on the duplicate paths is parsed against the per-block
  property schema** (`buildPropertiesSchema`) instead of being cast. Declared
  constraints — `maxLength`, numeric ranges, required keys — now apply to
  duplication too.
  → **Migration for both:** writes that relied on the old lax behaviour now fail with
  a validation error. Fix the payloads.

### Database

- **`merge_requests.source_branch_id`, `merge_requests.target_branch_id` and
  `approvals.branch_id` are nullable with `ON DELETE SET NULL`.** `deleteBranch`
  previously threw a raw foreign-key error on any branch that had been merged or had
  an approval request, so the standard branch → merge request → merge → delete
  workflow failed at the last step with an opaque 500 and left the branch permanently
  undeletable. Merge and approval history now survives the branch row. Open merge
  requests and publications still block deletion.
  → **Migration:** run `createcms generate` and apply a Drizzle migration
  (`drizzle-kit generate`) after upgrading.

## 0.3.0 — 2026-07-11

- **`getDiff`'s response shape and `moved` semantics changed.** The response is now
  `{ diff, tree, summary, sourceCommitId, targetCommitId, commonAncestorCommitId }`,
  with a new `view` query param (`'list' | 'tree' | 'both'`, default `'both'`).
  - `moved` is identity-based: a block is flagged only when it was reparented or is a
    true reorder outlier among surviving siblings (LIS-based). Siblings whose index
    merely shifted are no longer flagged — inserting one block among N siblings yields
    one diff entry instead of N+2.
  - `childrenReordered` is only set when the relative order of a parent's surviving
    common children actually changed, never for pure additions/removals.
  - A draft-slug change on the root yields `slugChange: { from, to }` instead of an
    opaque `modified`, and the reserved `__slug` key no longer leaks into returned
    version properties.
  - Modified entries carry `propertyChanges`, `typeChange`, and word-level `textDiff`
    segments; `tree` is the draft tree with per-node `diff` annotations and deleted
    blocks re-inserted as ghost nodes.
    → **Migration:** consumers reading the old top-level array must read `diff` (or
    `tree`) off the new envelope; request `view: 'list'` if you don't want the tree
    built. Diff UIs that counted on the noisy `moved` flag will see far fewer entries.
    New exported types: `ChangeType`, `PropertyChange`, `TextDiffSegment`, `MovedInfo`,
    `BlockChange`, `DiffSummary`, `BlockDiffAnnotation`, `AnnotatedBlockTreeNode`,
    `DiffView`.

- **`duplicateRoot`'s permission resource is `root`, not `block`.** It mints a new
  top-level root — the same privileged act `createRoot` guards as `root` — but its
  metadata said `block`, so a consumer granting `block:create` while denying
  `root:create` could create roots through duplication.
  → **Migration:** remap `duplicateRoot` from `block` to `root` in any
  `authMiddleware` permission matrix.

- **GET boolean query flags decode wire-safely.** `z.coerce.boolean()` turns the wire
  string `'false'` into `true`, so passing `false` over HTTP inverted the flag. The
  last affected flags — `listBranches` (`isDeletable` / `hasPublications` /
  `hasOpenMergeRequests`), `listRoots` (`hasPublications`), `notifications.list`
  (`unreadOnly`), `getBlockTree` (`raw` / `includeReferencePreviews`),
  `getPublishedContent` (`raw`), `listAssets` (`unfiled`) and the media asset gate
  (`download`) — now use `wireBooleanSchema`.
  → **Migration:** none for correct callers; in-process callers passing real booleans
  were never affected. HTTP callers that had worked _around_ the inversion (passing
  nothing to mean false, or `false` to mean true) must send the honest value.

- **`collectRootExecutionPlans` is removed.** It loaded every root with no limit and
  serially ran the full per-root planning bundle — an unbounded N+1. It had no
  callers, was never re-exported from the package entrypoint, and had no `./admin`
  subpath, so it was unreachable from outside the repo.
  → **Migration:** none expected. The production entry point, `runPruningPass`, does
  the budgeted equivalent (bounded by `maxRoots` / `maxDurationMs`).

- **Dependency floor:** `fast-xml-parser` moved from `^5.4.2` to `^5.7.0` so
  consumers cannot resolve a version affected by the `<5.7.0` prototype-pollution /
  XML-injection advisory.

## 0.2.12 — 2026-07-09

The largest breaking release in the project's history — shipped as a _patch_, before
the "minor is the breaking channel" rule existed. Eleven passes landed at once. If
you are upgrading across this version, budget real time.

### Security (fails secure by default)

- **`authMiddleware` is now required.** `createCMS` throws at construction if it is
  missing, so auth can never be silently absent. The undocumented `middleware` alias
  was removed.
  → **Migration:** to run with no auth on purpose (public/dev), pass the new
  `allowAnonymous()` export — byte-identical to the old omitted-middleware behaviour.
- **`media.allowedMimeTypes` defaults to an explicit allowlist:** `image/png`,
  `image/jpeg`, `image/webp`, `image/gif`, `video/mp4`, `video/webm`,
  `application/pdf`. No `image/*` / `video/*` wildcards, so `image/svg+xml` (a
  stored-XSS vector) is excluded by default. Uploads carrying file bytes are also
  checked against their real magic bytes, so a file declared `image/png` but
  containing SVG/HTML is rejected before it reaches storage.
  → **Migration:** re-add any format you relied on through the wildcards (avif, heic,
  mov, …) explicitly.
- **`user.exposeColumns` is required when a `user` table is configured.** It
  defaulted to _every_ column, leaking password hashes and tokens through `withUser`;
  `resolveUserConfig` now throws instead.
  → **Migration:** name the safe columns explicitly.
- **The multi-tenant slug is no longer read from the request body/query by default.**
  `resolveTenantSlug` returns the session-derived fallback and ignores
  request-supplied slugs unless you opt in with `{ allowRequestOverride: true }`
  (intended only behind an admin check).
  → **Migration:** opt in explicitly if you were relying on request-supplied tenants.
- **Approval endpoints no longer accept `reviewedBy` / `requestedBy` from the request
  body** (spoofable). The actor is derived from the auth context, and a reviewer must
  match one of `requestedReviewers`.
- **`search.query` applies the same read boundary as normal endpoints.** A result is
  returned only if its underlying entity is visible under the active scope, and
  notifications are filtered to the requesting user — closing a cross-tenant content
  leak and a cross-user notification-title leak.
  → **Migration:** none, but expect fewer results under a scoping plugin. With no
  scoping plugin active, behaviour is unchanged.

### Renames

Endpoints and parameters:

- `deleteRoot` → **`archiveRoot`** (it soft-archives).
- `search.search` → **`search.query`**, and its param `q` → **`search`**.
- `notifications.listNotifications` / `templates.listTemplates` /
  `variables.listVariables` → **`.list`**.
- `media.archiveAsset` → **`archiveAssets`**; `media.updateAssetStatus` →
  **`updateAssetsStatus`**.
- List direction unified to **`sortDirection`** (was `sortOrder` on `listAssets` /
  `listPublications`).
- `moveRoot` body param `sortOrder` → **`position`** (the _result_ field stays
  `sortOrder`).
- Template endpoints' `id` → **`templateId`**; `listFolders`' `parentId` →
  **`parentFolderId`**.
- `resolveConflicts` → **`applyConflictResolutions`**; `approve` →
  **`submitApproval`**; `reject` → **`submitRejection`**.
- `resolveTemplate` is now a **GET**.
- `moveFolder` accepts an explicit `null` parent (detach), matching `moveRoot` /
  `moveAssets`.

Config and types:

- `slug.root` → **`slug.prefix`**; `slug.allowRoot` → **`slug.allowIndex`**.
- Permission resources are singular: `'variables'` → **`'variable'`**, `'templates'`
  → **`'template'`**. A new exported `CMSPermissionResource` union makes a typo in a
  permission matrix a compile error.
- Context types standardised on the `Context` suffix: `CMSMiddlewareCtx`,
  `CMSProcedureCtx`, `CMSHandlerCtx`, `CMSSystemHandlerCtx` → `…Context`. The

- `cms.$notifications` → **`cms.$InferNotifications`**.
- `createBlocksRenderer` is **removed** — use `createContentRenderer`, or
  `createBlocksMap` + `BlocksRenderer` for the low-level path.
- Type-prefix cleanups: `ABTest*` → `AbTest*`; `GA4Payload` / `GA4ServerConfig` →
  `Ga4Payload` / `Ga4ServerConfig`; `CMSEvent` → `AnalyticsEvent`;

  `QueryState` / `MediaUploadState` / `MediaUploadFileState` / `MediaUploadOptions`

- The bundled multi-tenant plugin's id changed `multi-tenant` → **`multiTenant`**

- Removed exports: `$InferServerPlugin`, `InferPluginRealtimeEvents`, and the

- The vanilla client exposes `media.uploadState` (a real atom) instead of a mistyped
  `useUploadAssets`.

### Return shapes

Pre-1.0, these replaced the old shapes cleanly — there are no compat shims.

- **Commit envelope.** Every commit-producing mutation (`createRoot`, `createBlock`,
  `moveBlock`, `deleteBlock`, `duplicateBlock`, `updateBlock`, `updateBlocks`,
  `updateRoot`, `revertBranch`, `executeMerge`) returns
  `{ commit: { id, message, createdAt, createdBy }, … }` — replacing the three
  divergent keys `commitId` / `newCommitId` / `mergeCommitId`. A fast-forward
  `executeMerge` returns the resulting head commit instead of `mergeCommitId: null`.
  `updateBlocks` adds `changed: boolean` so a no-op save is distinguishable.
- **Entity envelope.** `createBranch` / `renameBranch` → `{ branch, isDeletable }`;
  `createMergeRequest` → `{ mergeRequest, hasConflicts, conflicts }`;
  `update` / `close` / `reopenMergeRequest` → `{ mergeRequest }`; `publishBranch` →
  `{ publication }` (now including `branchName`); approval mutations →
  `{ approval }`; comment message mutations → `{ message }`.
- **`getRootHistory` returns `{ commits, total, hasMore }`** (was
  `{ data, total, offset, limit }`). `listTemplates` / `listVariables` gain
  `limit` / `offset` / `search` and return `{ …, total, hasMore }`.
- **`getRoot` / `getRootBySlug` return the full `RootListItem`** (counts + path), not
  a bare summary.
- `updateAssetStatus` returns `{ updated, updatedIds, skipped }`;
  `deleteTemplate` / `deleteVariable` echo the deleted id (`{ templateId }` /
  `{ variableId }`) instead of `{ deleted: true }`; `deleteBlock` returns
  `deletedBlockIds`; `unpublishBranch` returns `unpublishedCommitId` /
  `unpublishedAt`; `uploadAssets` / `replaceAsset` return the full asset row.
- **Type fixes:** `getRootHistory.createdAt` and `createSignedUpload.expiresAt` are
  real `Date`s (were an ISO string / epoch-ms) on the server API.
- **`getDiff`, `checkConflicts` and `checkDivergence` are now GET** (were POST).
- **The HTTP client types every timestamp as the ISO `string` the wire actually
  delivers**, via a `Serialize<T>` mapped type at the client boundary. Server-side
  `cms.api.*` still returns real `Date`s.
  → **Migration:** client-side code that treated a timestamp as a `Date` must parse
  it. This makes an existing runtime reality visible to the type checker rather than
  changing behaviour.

### Content and validation

- **The root `slug` is versioned content.** `updateRoot` commits the slug to the
  branch instead of writing the global `roots.slug`; the live URL only changes when
  the branch is published, and `revertBranch` restores the slug with the content.
  `createRoot` leaves the live slug unset until the first publish. Uniqueness is
  enforced **at publish** (new typed `PUBLISH_SLUG_CONFLICT`; an atomic
  `publishRelease` rolls the whole release back on conflict) rather than at
  draft-write, and slug-change redirects are created at publish, so a never-published
  slug edit creates no redirect. Two branches editing the slug now produce a normal
  root-block merge conflict instead of a silent overwrite.
  → **Migration:** no schema migration (the draft slug rides an existing JSONB
  column), but run the `backfillDraftSlugs` script so existing entries have a draft
  slug to edit and re-publish. `parentRootId` / `moveRoot` are unchanged — a page move
  still changes the live URL immediately.
- **`updateBlocks` enforces structural validation**, matching the single-block
  routes: the posted root `blockId` must equal the entry root, every written block
  type must exist, each written block's properties are validated against its type
  schema, and placement is asserted over the tree. Validation is diff-scoped — new
  blocks strictly, updated blocks and the root with patch semantics, unchanged blocks
  untouched.
- **Stricter property validation:** `date` is validated as an ISO datetime;
  string/number properties honour declarative `minLength` / `maxLength` / `pattern` /
  `min` / `max`; and `image` / `reference` ids (including inside lists) must **exist**
  at write time.
  → **Migration:** writes that previously stored an invalid date or a dangling id now
  throw a validation error instead of failing later at render.
- **Required links are enforced:** a `required` link with an empty target
  (`url` / `rootId` / `email` / `phone`) is rejected instead of silently passing.
- **`executeMerge` blocks by default when an OPEN approval request exists** on the
  merge (previously only enforced behind the governance flags), mirroring
  `publishBranch`. A merge with no approval requests is unaffected.
- **`deleteCommentMessage` reports `operation: 'delete'`** to your `authMiddleware` /
  permission matrix (was `'update'`).
  → **Migration:** update any permission matrix keyed on `'update'` for that endpoint.
- **Reopening a comment thread emits a `threadReopened` notification** (was
  incorrectly `threadResolved`).
- **`getPublishedContent` no longer serialises the A/B control branch twice.** The
  control tree is the top-level `tree` / `properties`, and `abTest.variants` carries
  only the non-control variants.
  → **Migration:** read the control snapshot from the top-level tree.
- **`RevalidateEvent.slug` is renamed `storedSlug`**, and every URL-shaped value in
  `paths` is a leading-slash path, so using an event value as a Next.js cache tag no
  longer silently fails to bust.
  → **Migration:** read `event.paths` (for tags) or `event.storedSlug` (the bare
  slug).
- **List endpoints parse raw timestamps as UTC** (`listRoots`, root history,
  `listMergeRequests`), fixing an off-by-timezone `Date` on non-UTC hosts.

### Construction-time throws (previously silent)

- `createCMS` throws when a collection name collides with a reserved namespace
  (`admin` / `media` / `variables` / `templates` / `search` / `notifications` /
  `realtime`) or a plugin id, or isn't a URL-safe slug. Such a collection used to be
  silently clobbered and its routes 404'd.
- Plugin ids must be valid JS identifiers and every plugin endpoint path must be
  `/<id>/<method>`.
- Endpoint-conflict detection spans the full core + collection + plugin surface and
  **throws** on a duplicate path (was plugin-only and a `console.warn`).
- The config hook `action` is a closed union of endpoint keys (the `(string & {})`
  escape hatch is gone), so a misspelled action is a compile error rather than a
  silent no-op.
- `definePluginSchema` is curried — `definePluginSchema<CoreTables>()({ … })` — so
  the schema DSL is actually type-checked.

### Errors

- **State-conflict codes are now `409`** (were `400`): `BRANCH_NAME_ALREADY_EXISTS`,
  `MERGE_REQUEST_ALREADY_EXISTS`, `ROOT_HAS_CHILDREN`, `FOLDER_HAS_CONTENT`,
  `BRANCH_HAS_PUBLICATIONS`, `BRANCH_HAS_OPEN_MERGE_REQUESTS`.
  → **Migration:** update any client branching on the status code.
- **Removed never-thrown codes:** `MERGE_REQUEST_OUTDATED`, `COMMENT_BODY_REQUIRED`,
  `AB_TEST_WEIGHTS_INVALID`, and the decorative `media-optimize` `$ERROR_CODES`.
- Network/transport failures (offline/DNS/CORS) are now wrapped in `CMSClientError`
  (`status: 0`, `code: 'NETWORK_ERROR'`), so `err instanceof CMSClientError` holds
  where it previously didn't.
- The Next revalidate webhook returns the standard `{ message }` error shape and
  rejects malformed JSON with a clean `400`.

### Database

- **New tables:** `scheduled_publications`, `releases`, `release_items` (scheduled
  publishing/expiry and atomic multi-page releases).
- **Index changes:** a `(collection, slug)` index on `roots` for the public
  `getPublishedContent` slug lookup; the unused `bv_properties_gin` GIN index on
  `block_versions.properties` removed (it could not serve any existing query and only
  cost write amplification on the highest-churn table).
- **`createcms generate` now emits `export const cmsSchema = pgSchema('cms')`** (was
  `cms`), so `typeof cms` no longer collides with your `createCMS` instance.
  → **Migration:** run `createcms generate` and add a Drizzle migration. Update any
  import of the generated `cms` schema export to `cmsSchema`.

## 0.2.9 — 2026-06-29

- **The media gate is addressed by asset id: `GET /media/asset/{id}`** (was the asset
  slug). The id is exactly what content stores, so `<img src="/media/asset/{id}">`
  survives swapping the bytes behind an asset with no content change and no
  re-render. The redirect is short-cached (`max-age=300`, no longer `immutable`) so a
  swap propagates within minutes, while the object bytes stay long-cached at the CDN.
  → **Migration:** rewrite any hand-built `/media/asset/<slug>` URL to use the id. A

  plain asset-id string again on both the write and read paths; `resolveImageAssets`
  and the `ResolvedImage` type are gone.
  → **Migration:** anyone who adopted `{ id, slug }` in 0.2.8 reads the id directly
  and builds the gate URL from it.

## 0.2.4 — 2026-06-26

- **`branchProtection.protectMain` is removed, replaced by
  `branchProtection.protectPublishedBranches`** — and the semantics differ.
  `protectMain` protected the default branch _by name_; the replacement locks a
  branch against direct content mutations for exactly as long as it is **published**.
  This applies to _any_ published branch (a root can have several at once, e.g. A/B
  variants), not just the default one, and a never-published branch is freely
  editable. Enforced by a shared `assertBranchWritable` guard on every
  content-mutation route, including `revertBranch`; `createRoot` is never gated; still
  throws `PROTECTED_BRANCH` (403).
  → **Migration:** rename `protectMain: true` to `protectPublishedBranches: true`, and
  note that protection now follows publication state rather than branch name — changes
  go via another branch + merge, then a re-publish; unpublishing makes the branch
  directly editable again.

## 0.2.0 — 2026-06-20

- **`allowedChildBlocks` is removed, replaced by the collection-level `structure`
  map.** `structure` is keyed by parent block name (or the literal `'root'`) with
  three mutually exclusive modes per entry: open (`{}` / `{ accepts: '*' }`),
  whitelist (`{ accepts: ['x'] }`, fail-closed), or blacklist
  (`{ excludes: ['x'] }`, fail-open). A concrete `accepts` list together with
  `excludes` is a compile error, and block names autocomplete against the
  collection's blocks.
  → **Migration:** express the same intent with `structure` — e.g.
  `structure: { section: { accepts: ['featureItem'] } }`.
- **`allowChildren` is enforced on the server:** a block without
  `allowChildren: true` rejects all children (the root always accepts children).
  `createBlock`, `moveBlock` and `duplicateBlock` enforce the rules and throw the new
  `BLOCK_NOT_ALLOWED_IN_PARENT` error; the visual editor reads the same rules for
  drop-zone gating, so the two cannot diverge.
  → **Migration:** declare `allowChildren: true` on every block that holds children.
