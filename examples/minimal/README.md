# @createcms/core — minimal example

The Quickstart wiring as a runnable Next.js app: a `pages` collection, the
mounted CMS HTTP router, and one published page read back and rendered by path.

This example runs on **PGlite** (an in-process Postgres) so it needs no external
database. The database is in-memory and starts empty on every boot, so the app
creates and publishes a demo `/welcome` page on first read (`lib/cms-data.ts`).

## File tree

```
examples/minimal
├─ app/
│  ├─ api/cms/[[...rest]]/route.ts   # mounts cms.router (GET/POST)
│  ├─ layout.tsx
│  └─ page.tsx                       # force-dynamic render of /welcome
├─ db/
│  └─ schema.ts                      # GENERATED by `createcms generate`
├─ lib/
│  ├─ collections.ts                 # the `pages` collection
│  ├─ cms.ts                         # createCMS(...) — discovered by the CLI
│  ├─ cms-client.ts                  # type-safe browser client
│  ├─ cms-data.ts                    # bootstraps + seeds demo content
│  └─ db.ts                          # PGlite + Drizzle, applies the schema
├─ next.config.mjs
├─ package.json
└─ tsconfig.json
```

## Run it

```bash
# from the repo root — links the workspace
bun install

cd examples/minimal
bun run dev      # http://localhost:3000
```

## Regenerating the schema

`db/schema.ts` is committed so the build works out of the box. The schema is
**content-agnostic** (core versioning tables + any plugin schema); your
collections never appear in it. Regenerate it only when you add or change a
plugin that ships schema:

```bash
# IMPORTANT: run the CLI with Node (the CLI's config loader relies on Node's
# module hooks; Bun's interop differs).
node ../../packages/cms/dist/bin/createcms.js generate
# in a published app this is just: npx createcms generate
```

### Applying the schema to a real database

This example applies the schema to in-memory PGlite at startup (see `lib/db.ts`).
A production app would instead point Drizzle at a persistent Postgres and apply
the schema with drizzle-kit:

```bash
bun run db:generate   # drizzle-kit generate — diff schema into SQL migrations
bun run db:migrate    # drizzle-kit migrate  — apply them to your database
```

The default PGlite path is in-memory and needs no migrations; these scripts read
`drizzle.config.ts` and connect via `DATABASE_URL`, so run them only once you
point `DATABASE_URL` at a real Postgres.

## Key constraints

- **Every page that reads CMS data must be `export const dynamic = 'force-dynamic'`.**
  This keeps `next build` from touching the database at build time.
- Render with `BlocksRenderer` / `createBlocksMap` imported from
  **`@createcms/core/react/blocks`** in Server Components. The `@createcms/core/react`
  barrel also re-exports the client, which would pull React hooks into a Server
  Component.
